## Первый запуск

DITA Studio работает на Windows, Linux и macOS: распакуйте архив своей системы со страницы
релизов и запустите `DitaStudio.Desktop` (на Windows — `DitaStudio.Desktop.exe`). Прежняя
WPF-версия для Windows (`DitaStudio.exe`) в релизы больше не входит — последняя сборка есть в
v4.0.0, дальше её можно собрать из исходников; ниже описана основная версия, отличия легаси
отмечены отдельно.

**Файл → Открыть папку проекта…** (`Ctrl+Shift+O`) — выберите папку, в которой лежат
карта (`.ditamap`) и топики. Редактор сканирует папку целиком: строит дерево файлов
слева, разбирает ключи (`keydef`) для `keyref`, определяет типы документов.

Последние восемь открытых папок доступны в **Файл → Недавние проекты** — список
сохраняется между запусками редактора; папки, которых больше нет на диске, не показываются.

Чтобы попробовать редактор без своих файлов, откройте один из готовых примеров:

| Проект | Что показывает |
|---|---|
| `samples/DitaStudioGuide` | Руководство по самому DITA Studio — сноски, разрывы страниц, объединение ячеек |
| `samples/GuideSample` | Небольшой учебный проект: концепция, задачи, справка, устранение неполадки, глоссарий |

Настройки проекта (условия сборки, связанный `.ditaval`, пользовательский CSS,
колонтитулы PDF, проекты-источники ключей, внешний DTD) сохраняются вместе с проектом и
подхватываются при следующем открытии папки.

## Создание проекта с нуля

Проект DITA Studio — это обычная папка: в ней лежат карты (`.ditamap`), топики (`.dita`),
картинки и служебные файлы настроек `.ditastudio-*`. Никакого отдельного «файла проекта»
создавать не нужно. Ниже — путь от пустой папки до готового сайта.

### 1. Подготовьте папку

Создайте папку в Проводнике и сразу разложите в ней подпапки по типам содержимого.
Диалог «Создать документ» предлагает только уже существующие папки, поэтому удобнее
создать их заранее:

```
MyProduct/
  myproduct.ditamap     главная карта публикации
  keys.ditamap          (по желанию) ключи отдельной картой
  concepts/             концепции — «что это и зачем»
  tasks/                задачи — «как сделать»
  reference/            справка — параметры, таблицы, синтаксис
  troubleshooting/      устранение неполадок
  glossary/             статьи глоссария
  reusable/             общие фрагменты для conref
  images/               рисунки
```

Редактор не сканирует скрытые папки и папки `out`, `bin`, `obj`, `temp`, `node_modules`.
Сборку по умолчанию он предлагает класть в `out` — она не засорит дерево проекта.

### 2. Откройте папку

**Файл → Открыть папку проекта…** (`Ctrl+Shift+O`) и выберите папку. Пустая папка —
нормальный проект: дерево на вкладке «Проект» просто будет пустым.

### 3. Создайте карту

**Файл → Создать документ…** (`Ctrl+N`) → **Карта**. Заголовок — название будущей
публикации, папка — корень проекта. Для книги с главами, частями, приложениями и
оглавлением выберите **Карта книги** (`bookmap`), подробнее — в разделе
[«Карты: map, bookmap, subjectScheme»](#карты-map-bookmap-subjectscheme).

### 4. Создайте первые топики

Снова `Ctrl+N` и выберите тип топика — от него зависит, какую структуру редактор будет
разрешать внутри (см. [«Типы топиков»](#типы-топиков)). Короткое правило выбора:

- объясняете, *что* это и *зачем* — **Концепция**;
- описываете, *как* сделать, по шагам — **Задача**;
- приводите данные для справки (параметры, коды, команды) — **Справка**;
- разбираете «не работает — почему — что делать» — **Устранение неполадки**;
- определяете термин — **Статья глоссария**.

Редактор предложит имя файла и `id` из заголовка (кириллица транслитерируется). Новый
документ открывается в режиме «Автор» с заготовкой: заполните краткое описание
(`shortdesc`) — одно-два предложения о том, что даёт топик, — и основную часть.

### 5. Соберите карту

Вкладка **Карта** слева → выберите карту в списке сверху:

- **+ Топик** добавляет ссылку на существующий файл. Новая строка встаёт после выделенной
  (или в конец карты, если ничего не выделено);
- **+ Раздел** добавляет заголовок раздела без собственного топика (`topichead` с текстом
  «Новый раздел»). Чтобы переименовать его, откройте карту двойным щелчком на вкладке
  «Проект» и исправьте текст `navtitle`;
- **→** вкладывает выделенную строку в предыдущую, **←** выносит из вложения, **↑ / ↓** и
  перетаскивание меняют порядок.

Порядок строк карты — это порядок и вложенность страниц в публикации.

### 6. Заведите ключи

Всё, что повторяется и может измениться, — название продукта, версию, адрес сайта,
ссылку на общий раздел — стоит оформить ключом. Откройте карту, переключитесь в режим
**Исходный код** и добавьте определения перед ссылками на топики:

```xml
<keydef keys="product">
  <topicmeta><keywords><keyword>МойПродукт</keyword></keywords></topicmeta>
</keydef>
<keydef keys="install" href="tasks/install.dita"/>
```

После сохранения (`Ctrl+S`) ключи появятся на вкладке **Ключи**. В тексте топика
используйте их так: `<keyword keyref="product"/>`, `<xref keyref="install"/>`. Подробно —
в разделе [«Ключи, ключевые слова и предметный указатель»](#ключи-ключевые-слова-и-предметный-указатель).

### 7. Проверьте проект

**F7** — проверка всего проекта. Ошибки (недопустимый порядок элементов, битые ссылки,
необъявленные ключи, повторяющиеся `id`) нужно исправить до публикации;
предупреждения и сведения (нет `shortdesc`, картинка без `alt`) — по ситуации.
Двойной щелчок по строке переходит к месту ошибки.

### 8. Посмотрите и опубликуйте

Вкладка **Предпросмотр** у каждого документа показывает топик так, как он будет
выглядеть в публикации. Когда всё готово, **F5** собирает HTML-сайт по выбранной карте;
там же, в меню **Публикация**, — единый HTML, PDF и DOCX.

### 9. Дальше по мере надобности

- разные варианты одного руководства (для разных моделей, аудиторий) — атрибуты
  `product`/`audience`/`platform` и [условия сборки](#условия-сборки-и-ditaval);
- общие фрагменты текста — [вынесение в conref](#рефакторинг-id-файлы-conref);
- фирменное оформление — «Публикация → Пользовательский CSS…»;
- общие ключи для нескольких проектов — [проекты-источники ключей](#ключи-ключевые-слова-и-предметный-указатель).

### Советы по устройству проекта

- **Один топик — одна мысль.** Топик должен читаться отдельно от соседей: его могут
  показать в поиске, по ссылке или в другой публикации. Если заголовок приходится
  писать через «и», это, скорее всего, два топика.
- **`id` корневого элемента — стабильный.** На него ссылаются `href` и `conref`; менять
  его лучше через «Структура → Переименовать id…» — ссылки обновятся сами.
- **Имя файла = `id` топика.** Так проще искать и переносить файлы; переносите их правым
  щелчком на вкладке «Проект», а не в Проводнике, — тогда редактор обновит ссылки.
- **Язык документа** указывает атрибут `xml:lang` корневого элемента (заготовки ставят
  `ru-RU`). Держите его верным: по нему другие инструменты DITA и системы перевода
  определяют язык текста.
- **Контроль версий.** Проект удобно хранить в git. Папку сборки (`out/`) в репозиторий
  не добавляйте. Файлы `.ditastudio-*` — настройки проекта (условия сборки, связанный
  `.ditaval`, CSS, колонтитулы PDF); добавьте их, если настройки нужны всем, кто работает
  с проектом, но проверьте, что пути в них не абсолютные.

## Интерфейс окна

- **Сверху** — меню и панель инструментов. На панели (слева направо): открыть проект,
  создать и сохранить документ; отмена и повтор структурных правок; полужирный, курсив,
  подчёркнутый, код в строке; перекрёстная ссылка, изображение, сноска; раздел, абзац,
  нумерованный и маркированный список; таблица, вставка строки выше / ниже, удаление
  строки, вставка столбца слева / справа, удаление столбца, объединение ячеек по
  горизонтали и вертикали, разделение ячейки; перемещение и удаление элемента; проверка и
  сборка. Подсказка с названием кнопки появляется при наведении, в узком окне панель
  переносится на вторую строку.
- **Слева** — три вкладки: **Проект** (дерево файлов, кнопки «Обновить» и «Создать…»),
  **Карта** (структура публикации выбранной карты) и **Ключи** (список `keydef` и их целей).
- **По центру** — вкладки открытых документов; у каждого документа три подрежима:
  **Автор** (визуальное редактирование), **Исходный код** (XML с подсветкой и
  автодополнением), **Предпросмотр** (результат публикации).
- **Справа** — три вкладки: **Атрибуты** выделенного элемента, **Вставка** (палитра
  допустимых элементов, `Ctrl+E`), **Структура** (дерево топика, переход по клику).
- **Внизу** — **Проверка** (результаты проверки), **Поиск** (по проекту), **Журнал
  сборки** (вывод последней публикации).
- **Строка состояния** внизу окна показывает путь текущего элемента (XPath-подобный) и
  итог последней операции.

## Создание и редактирование документов

**Файл → Создать документ…** (`Ctrl+N`) — выбираете заготовку (концепция, задача,
справка, устранение неполадки, статья глоссария, карта), редактор предлагает имя файла
и `id`, исходя из заголовка (кириллица транслитерируется). Чем типы отличаются и какой
выбрать — в разделе [«Типы топиков»](#типы-топиков). Если в проекте есть карта, новый топик
сразу добавляется в карту, выбранную на вкладке **Карта**, — после выделенной там строки
(без выделения — в конец карты); карта открывается во вкладке с правкой, её нужно сохранить.
Новая карта в другую карту не добавляется.

В режиме **Автор** каждый блочный элемент — своя область редактирования. Блоки-обёртки
(`div`, `bodydiv`, `section`, `sectiondiv`, `fig` и их специализации) обведены полосой слева
с подписью — именем элемента и классом `outputclass`, если он задан. Сноски (`fn`) не
разрывают текст: в строке на их месте плашка «сноска 1», «сноска 2»…, а сам текст каждой
сноски правится в области **Сноски** внизу топика — под номером, как в печатной книге
(`Enter` в тексте сноски ничего не делает: сноска — один абзац). Удалите плашку из
текста — сноска уйдёт и из области. Подписи отдельных строк (`p`, `li`, `title`…) слева включаются и выключаются
пунктом **Структура → Показывать имена элементов**.

- `Enter` в конце блока открывает у курсора **подсказку**: какой элемент вставить дальше.
  Первая строка — обычное действие Enter (следующий абзац, шаг задачи, пункт списка),
  поэтому двойной `Enter` работает как раньше; ниже — все элементы, допустимые после блока, а
  в конце пункта списка или раздела — и после самого списка или раздела; справа — описание
  выбранного элемента. Набор текста фильтрует список, `Enter` или двойной щелчок — вставить,
  `Esc` — закрыть. Подсказку можно выключить: «Структура → Подсказка по Enter». `Enter` в
  середине текста разбивает его по позиции курсора;
- `Backspace` в начале блока объединяет его с предыдущим;
- `Tab` / `Shift+Tab` в списке или в шагах задачи меняют уровень вложенности;
- выделите текст и нажмите `Ctrl+B` / `Ctrl+I` / `Ctrl+U` / `` Ctrl+` `` /
  `Ctrl+Shift+U`, чтобы обернуть его в `b` / `i` / `u` / `codeph` / `uicontrol`;
  `Ctrl+Shift+Space` снимает оформление;
- слова с ошибками подчёркиваются волнистой линией (проверка орфографии по словарям
  Hunspell, русский и английский), правый клик по слову предлагает варианты исправления и
  «Пропустить все»; код, пути к файлам, имена команд и параметров, ключевые слова не
  проверяются, как и аббревиатуры (`DITA`) и слова с цифрами (`x64`). В том же меню —
  «Вырезать», «Копировать», «Вставить» (вставляется только простой текст) и подменю
  **Вставить элемент**: сноска, изображение, перекрёстная ссылка, таблица, а также все
  элементы, допустимые у курсора, — «В строку текста» (термин, код, элемент интерфейса…)
  и «Блок после текущего» (абзац, список, примечание…); «Все элементы…» открывает панель
  **Вставка**;
- панель **Вставка** справа (`Ctrl+E`) показывает только элементы, допустимые в текущей
  позиции — список можно отфильтровать вводом текста, вставка — двойным щелчком; частые
  блоки (абзац, списки, примечание, блок кода) есть и в меню **Вставка**. Блочный элемент
  встаёт после текущего блока, фразовый (термин, сноска, изображение) — на место курсора:
  выделенный текст оборачивается им, а без выделения внутрь ставится выделенная заготовка,
  которую сразу можно заменить набором;
- **Ctrl+Shift+↑** / **Ctrl+Shift+↓** переставляют текущий элемент, не трогая мышь;
  удаление — через меню «Структура → Удалить элемент» (с подтверждением).

**Изображения** показываются самой картинкой — и отдельным блоком (в `fig`), и внутри строки
текста. Размер меняется мышью: наведите указатель на картинку и потяните за квадратный
маркер в правом нижнем углу, пропорции сохраняются; подсказка показывает размер в пикселях.
В файл записывается стандартный атрибут `width` (в `px`), `height` снимается; правка
отменяется, как и другие. Публикация (HTML, PDF, DOCX) берёт этот размер.

Не каждый элемент редактируется как обычный текст: перекрёстные ссылки
без текста и вставки через `conref`/`conkeyref` показываются нередактируемой «плашкой» —
изменить их атрибуты или содержимое можно в режиме **Исходный код**. Служебные блоки
(`prolog`, `topicmeta`, `metadata`) показываются свёрнутым XML по той же причине.

### Оформление текста без CSS

Выравнивание, размер шрифта и цвет задаются кнопками на панели инструментов или в
контекстном меню **Оформление** (правая кнопка мыши в тексте) — знать CSS и XML не нужно.
В файл они записываются стандартным для DITA способом — классом `outputclass`
(`align-center`, `size-10`, `color-red`), а публикация (HTML, PDF, DOCX) превращает его в
оформление. CSS проекта может переопределить вид этих классов.

- **Выравнивание** — по левому краю, по центру, по правому краю, по ширине — действует на
  блок под курсором: абзац, заголовок, пункт списка, ячейку таблицы. У ячейки таблицы CALS
  выравнивание пишется в её стандартный атрибут `align`. В «Авторе» блок с выравниванием по
  центру или вправо сдвигается целиком: короткий текст (заголовок, подпись, ячейка) стоит
  так же, как в публикации, а у длинного абзаца строки внутри редактора остаются левыми —
  в публикации они выровнены полностью.
- **Размер шрифта** (8–28 пт) — список «Размер» на панели или «Оформление → Размер шрифта».
  Работает как в Word: выделенный текст получает размер (в файле — фраза
  `<ph outputclass="size-10">`), выделенный целиком абзац — класс на самом абзаце, а без
  выделения у курсора появляется заготовка «текст» нужного размера — набирайте дальше, и
  текст пойдёт этим размером. Повторный выбор для того же фрагмента меняет размер, а не
  вкладывает фразу в фразу. «Обычный» снимает размер с выделения (фраза без других
  атрибутов исчезает, текст остаётся). В «Авторе» размер виден сразу.
- **Нумерованный абзац (пункт)** — кнопка «№» на панели, «Оформление → Нумерованный
  абзац» или меню «Структура». При публикации абзац получает номер по заголовкам, как пункт
  по ГОСТ 2.105: во 2-й главе, 3-м разделе — 2.3.1, следующий — 2.3.2; подзаголовок того же
  уровня продолжает счёт. Для этого включите нумерацию заголовков («Оформление DOCX →
  Нумеровать заголовки»); тогда номера получают и заголовки — в DOCX, едином HTML и PDF, и на
  сайте. Без нумерации заголовков абзацы нумеруются просто 1, 2, 3 — заново после каждого
  заголовка. В «Авторе» у такого абзаца слева «№» (сам номер зависит от места в карте), в
  предпросмотре одного топика — простой счёт.
- **Положение на листе (PDF, DOCX)** — «Оформление → Положение на листе» в контекстном меню
  или меню «Структура». Абзац, рисунок, таблица или заметка ставится на отдельную страницу в
  одну из девяти областей: вверху, посередине или внизу — слева, по центру или справа (гриф
  внизу листа, схема по центру). «Обычное (в тексте)» возвращает блок в текст. Курсор в
  подписи рисунка или ячейке таблицы ставит на лист весь рисунок или таблицу; блок внутри
  списка, таблицы или заметки на лист не ставится (пункт меню недоступен). В «Авторе» над
  блоком — пометка «▣ Отдельный лист · внизу справа». В PDF блок занимает свою страницу, текст
  продолжается со следующей; в DOCX — это отдельный раздел Word с вертикальным выравниванием
  страницы, те же колонтитулы и параметры листа. На сайте и в предпросмотре блок остаётся в
  тексте. В файле — класс `outputclass="place-bottom-right"` и т. п.
- **Цвет текста** — кнопка «А» с цветной полосой на панели (палитра: красный, оранжевый,
  зелёный, синий, фиолетовый, серый и «Без цвета») или «Оформление → Цвет текста». Правила
  те же, что у размера: выделение, весь абзац, заготовка у курсора; в файле — класс
  `color-red` и т. п.

Отмена (`Ctrl+Alt+Z` / `Ctrl+Alt+Y`) относится к структурным правкам и хранится как
снимки XML; обычный набор текста отменяется самим текстовым полем по `Ctrl+Z`/`Ctrl+Y` —
это два независимых стека.

**F1** (или «Справка → Об элементе под курсором») показывает описание элемента из
встроенного каталога: контент-модель, допустимые атрибуты, модуль.

## Типы топиков

В DITA текст делится на небольшие самостоятельные части — **топики**. Все топики устроены
одинаково снаружи:

| Часть | Элемент | Зачем |
|---|---|---|
| Заголовок | `title` | Обязателен. Становится заголовком страницы и строкой оглавления. |
| Краткое описание | `shortdesc` (или `abstract`) | Одно-два предложения о сути топика. Показывается в подсказках ссылок и результатах поиска; проверка напоминает, если его нет. |
| Пролог | `prolog` | Метаданные: автор, даты, ключевые слова (`metadata/keywords`), условия. В публикацию как текст не выводится. |
| Тело | `body`, `conbody`, `taskbody`… | Основное содержимое — его структура и отличает типы друг от друга. |
| Связанные ссылки | `related-links` | Ссылки «Смотрите также», заданные в самом топике (см. также таблицу соответствий карты). |
| Вложенные топики | любой топик | Топик может содержать дочерние топики после своего тела — удобно для коротких связанных частей в одном файле. |

Тип топика определяет, что можно положить в тело. Редактор знает эти правила: панель
**Вставка** показывает только допустимые элементы, `Enter` создаёт следующий подходящий
элемент (например, следующий шаг задачи), а проверка сообщает, если порядок нарушен.

| Тип | Корень / тело | Для чего | Заготовка в «Создать документ» |
|---|---|---|---|
| Концепция | `concept` / `conbody` | Объяснение: что это, как устроено, зачем | Концепция |
| Задача | `task` / `taskbody` | Пошаговая инструкция | Задача |
| Справка | `reference` / `refbody` | Данные для поиска глазами: параметры, коды, синтаксис | Справка; Таблица (без заголовка) |
| Устранение неполадки | `troubleshooting` / `troublebody` | Признак → причина → решение | Устранение неполадки |
| Статья глоссария | `glossentry` / `glossBody` | Определение одного термина | Статья глоссария |
| Группа глоссария | `glossgroup` | Несколько статей глоссария в одном файле | — (корень меняется в исходном коде) |
| Универсальный топик | `topic` / `body` | Когда не подходит ни один специализированный тип | Универсальный топик |
| Учебные топики | `learningOverview`, `learningContent`, `learningSummary`, `learningAssessment`, `learningPlan` | Учебные курсы (DITA Learning and Training) | — (корень меняется в исходном коде) |

### Концепция (`concept`)

Отвечает на вопросы «что это?» и «зачем?»: описание продукта, принципа работы,
устройства, понятия. В концепции не должно быть пошаговых инструкций — их место в задаче,
на которую концепция может сослаться.

Тело `conbody` принимает обычные блоки: абзацы, списки, таблицы, рисунки, примечания,
блоки кода, а также разделы `section` со своими заголовками и примеры `example`.

```xml
<concept id="about-backup">
  <title>Резервное копирование</title>
  <shortdesc>Резервная копия защищает данные от сбоя диска и случайного удаления.</shortdesc>
  <conbody>
    <p>Программа сохраняет копию раз в сутки…</p>
    <section>
      <title>Что входит в копию</title>
      <ul><li>настройки;</li><li>журнал событий.</li></ul>
    </section>
  </conbody>
</concept>
```

### Задача (`task`)

Инструкция, которую читатель выполняет по шагам. Порядок частей `taskbody` строгий —
редактор не даст его нарушить:

| Часть | Элемент | Содержание |
|---|---|---|
| Условия | `prereq` | Что должно быть готово до начала (права, установленная программа). |
| Контекст | `context` | Зачем и когда выполняется задача. |
| Шаги | `steps` (нумерованные), `steps-unordered` (порядок не важен) или `steps-informal` (свободный текст) | Сами действия. |
| Результат | `result` | Что получится в конце. |
| Если не получилось | `tasktroubleshooting` | Что делать, если результат не достигнут. |
| Пример | `example` | Пример выполнения (может быть несколько). |
| Дальнейшие действия | `postreq` | Что сделать после. |

Все части необязательны, но идут только в этом порядке.

**Шаг** `step` начинается с команды `cmd` — одного действия в повелительном наклонении
(«Нажмите…», «Выберите…»). После команды в шаге могут идти пояснение `info`, подшаги
`substeps`, пример `stepxmp`, варианты `choices` или таблица вариантов `choicetable`,
примечание `note`; в конце — результат шага `stepresult` и что делать при сбое
`steptroubleshooting`. Атрибут `importance="optional"` помечает необязательный шаг.
Группы шагов можно разделять подзаголовками `stepsection`.

В режиме «Автор» `Enter` в конце команды создаёт следующий шаг, `Tab` превращает шаг в
подшаг предыдущего, `Shift+Tab` — обратно.

```xml
<task id="make-backup">
  <title>Создание резервной копии</title>
  <shortdesc>Сохраните копию данных перед обновлением программы.</shortdesc>
  <taskbody>
    <prereq><p>Нужны права администратора.</p></prereq>
    <steps>
      <step><cmd>Откройте меню <uicontrol>Сервис</uicontrol>.</cmd></step>
      <step>
        <cmd>Выберите <uicontrol>Резервная копия</uicontrol>.</cmd>
        <stepresult><p>Откроется окно выбора папки.</p></stepresult>
      </step>
      <step importance="optional"><cmd>Включите сжатие.</cmd></step>
    </steps>
    <result><p>Копия появится в выбранной папке.</p></result>
  </taskbody>
</task>
```

### Справка (`reference`)

Сведения, которые не читают подряд, а ищут глазами: параметры, коды ошибок, команды,
технические характеристики. Тело `refbody` состоит из разделов `section`, синтаксиса
`refsyn`, примеров `example`, таблиц (`table`, `simpletable`) и таблиц свойств
`properties`.

`properties` — специальная таблица «свойство — значение — описание»: строка `property`
содержит `proptype`, `propvalue`, `propdesc`, необязательная шапка — `prophead`. В режиме
«Автор» она правится по ячейкам, как обычная таблица.

```xml
<reference id="settings">
  <title>Параметры</title>
  <shortdesc>Параметры файла настроек и их значения по умолчанию.</shortdesc>
  <refbody>
    <properties>
      <property>
        <proptype>timeout</proptype>
        <propvalue>30</propvalue>
        <propdesc>Время ожидания ответа, с.</propdesc>
      </property>
    </properties>
  </refbody>
</reference>
```

#### Топик без заголовка

`<title>` у топика обязателен по стандарту DITA, но может быть пустым. Если стереть текст
заголовка, топик публикуется без него: в HTML, PDF и DOCX заголовок не печатается, в
оглавление топик не попадает, а в карте, навигации сайта и подписях ссылок он называется
по первому непустому заголовку внутри (например, по подписи таблицы) или по имени файла.
Проверка выдаёт об этом только информационное сообщение. Заготовка **Таблица (без
заголовка)** в «Создать документ» — готовый такой топик: пустой заголовок и таблица,
подписью которой становится введённое название.

### Устранение неполадки (`troubleshooting`)

Разбор проблемы по схеме «признак → причина → решение». Тело `troublebody`:

- `condition` — что видит пользователь (признак);
- один или несколько `troubleSolution` — вариантов решения, в каждом:
  - `cause` — возможная причина;
  - `remedy` — что сделать: необязательный заголовок, кто выполняет (`responsibleParty`)
    и шаги `steps`, как в задаче.

Если причин несколько, делайте несколько `troubleSolution` в одном топике — от самой
вероятной к самой редкой.

```xml
<troubleshooting id="no-start">
  <title>Программа не запускается</title>
  <shortdesc>Что делать, если после двойного щелчка ничего не происходит.</shortdesc>
  <troublebody>
    <condition><p>Окно программы не появляется.</p></condition>
    <troubleSolution>
      <cause><p>Не установлен .NET 8.</p></cause>
      <remedy>
        <steps><step><cmd>Установите .NET Desktop Runtime 8.</cmd></step></steps>
      </remedy>
    </troubleSolution>
  </troublebody>
</troubleshooting>
```

### Статья глоссария (`glossentry`) и группа (`glossgroup`)

Одна статья — один термин. Вместо заголовка — сам термин `glossterm`, вместо краткого
описания — определение `glossdef`. Необязательное тело `glossBody` уточняет термин:

- `glossSurfaceForm` — полная форма при первом упоминании («Программируемый логический
  контроллер (ПЛК)»);
- `glossAlt` — альтернативные формы: сокращение `glossAcronym`, аббревиатура
  `glossAbbreviation`, краткая форма `glossShortForm`, синоним `glossSynonym`;
- `glossUsage`, `glossScopeNote` — как и где употреблять термин.

Статьи удобно подключать к тексту через ключи: определите ключ на статью в карте
(`<keydef keys="plc" href="glossary/plc.dita"/>`) и пишите в тексте
`<abbreviated-form keyref="plc"/>`. DITA Studio выводит на этом месте сокращение
(`glossAcronym` или `glossAbbreviation`), а если его нет — сам термин.

Несколько коротких статей можно держать в одном файле: корень `glossgroup` с заголовком
и статьями внутри. Заготовки для группы нет — создайте статью глоссария и замените
корень в режиме «Исходный код» (вместе со строкой `DOCTYPE`).

### Универсальный топик (`topic`)

Базовый тип без ограничений на структуру: тело `body` принимает любые блоки. Подходит для
вводных страниц, юридических текстов, всего, что не является ни объяснением, ни
инструкцией, ни справкой. Если текст ложится в один из специализированных типов, лучше
выбрать его: структура помогает и автору, и читателю, и проверке.

### Учебные топики (`learning*`)

Типы DITA Learning and Training — обзор курса `learningOverview`, учебный материал
`learningContent`, итоги `learningSummary`, проверка знаний `learningAssessment`, план
обучения `learningPlan`. Они есть в каталоге редактора: проверяются, отображаются и
предлагаются в панели «Вставка», но готовой заготовки для них нет. Создайте
универсальный топик и в режиме «Исходный код» замените корневой элемент и строку
`DOCTYPE`, например:

```xml
<!DOCTYPE learningContent PUBLIC "-//OASIS//DTD DITA Learning Content//EN" "learningContent.dtd">
<learningContent id="lesson1">
  <title>Урок 1</title>
  …
</learningContent>
```

Проверка (`F7`) подскажет, что допустимо внутри.

## Карты: map, bookmap, subjectScheme

Карта не содержит текста — она задаёт, **какие** топики входят в публикацию, **в каком
порядке** и **с какой вложенностью**. Один и тот же топик может входить в несколько карт:
например, в полное руководство и в краткую памятку.

### Обычная карта (`map`)

| Элемент | Что делает |
|---|---|
| `title` | Заголовок публикации. |
| `topicref href="…"` | Ссылка на топик; вложенные `topicref` — подразделы. |
| `topichead` | Заголовок раздела без собственной страницы; текст — в `topicmeta/navtitle`. |
| `topicgroup` | Группа ссылок без заголовка — только чтобы объединить их общими атрибутами. |
| `keydef keys="…"` | Определение ключа (см. [ключи](#ключи-ключевые-слова-и-предметный-указатель)). В оглавление не попадает. |
| `mapref href="….ditamap"` | Подключение другой карты целиком — удобно, чтобы собирать большую публикацию из частей. |
| `reltable` | Таблица соответствий: связи «Смотрите также» между топиками (кнопка «Таблица соответствий…» на вкладке «Карта»). |

Полезные атрибуты `topicref`:

- `navtitle` (или `topicmeta/navtitle`) — свой текст строки оглавления вместо заголовка
  топика;
- `processing-role="resource-only"` — топик нужен для ссылок и ключей, но в публикацию
  отдельной страницей не выходит;
- `keyscope` — своя область ключей для ветки карты.

Условные атрибуты (`product`, `audience`, `platform`…) на самих `topicref` при сборке
пока не учитываются — ставьте их на элементы внутри топиков, там условия работают.

### Карта книги (`bookmap`)

Для публикаций в виде книги (PDF, DOCX). Вместо `title` — `booktitle` с основным
заголовком `mainbooktitle`; дальше идут:

- `frontmatter` — начало книги: перечни `booklists` (например, оглавление `toc`),
  предисловие `preface`, уведомления `notices`;
- `part` — части, внутри которых `chapter`;
- `chapter` — главы (можно без частей);
- `appendix` / `appendices` — приложения;
- `backmatter` — завершающая часть.

В главу вкладываются обычные `topicref`. Заготовка «Карта книги» уже содержит
`booktitle` и `frontmatter` с оглавлением.

### Схема категорий (`subjectScheme`)

Карта особого вида: описывает допустимые значения условных атрибутов (`subjectdef`,
`enumerationdef`) — например, что `product` может быть только `basic` или `pro`. DITA
Studio знает структуру схемы (её можно создать через «Создать документ» и проверить), но
значения атрибутов в топиках по ней **не** проверяет; список значений для условий сборки
редактор собирает из фактически использованных в проекте.

## Вставка таблиц, изображений, ссылок и сносок

- **Таблица** («Вставка → Таблица…») — диалог задаёт число строк/столбцов, наличие
  заголовка. Объединение ячеек — поставьте курсор в ячейку и нажмите `Ctrl+Alt+→`
  (объединить со следующей по горизонтали, `namest`/`nameend`) или `Ctrl+Alt+↓`
  (со строкой ниже, `morerows`); содержимое поглощённых ячеек не теряется.
  Название таблицы (`title`) печатается как «Таблица N. Название»; если название пустое,
  подписи нет и номер не расходуется — следующая таблица с названием получит тот же номер.
  Так же работают рисунки: «Рисунок N.» только у рисунков с названием.
- **Строки и столбцы** — правая кнопка мыши в ячейке (или «Структура → Таблица»):
  вставить строку выше / ниже, удалить строку, вставить столбец слева / справа, удалить
  столбец, объединить с ячейкой справа / снизу, разделить ячейку, атрибуты ячейки,
  свойства таблицы. Объединённые ячейки учитываются: строка, вставленная посреди
  растянутой вниз ячейки, её удлиняет; при удалении строки растянутая ячейка переезжает в
  следующую со своим текстом; новый столбец внутри объединения по горизонтали его
  расширяет. У `simpletable` работают и строки, и столбцы (`relcolwidth` и `keycol`
  пересчитываются), у `properties` и `choicetable` — только строки: их столбцы заданы
  типом таблицы. Последнюю строку тела и последний столбец удалить нельзя.
- **Ширина столбцов и высота строк — мышью.** Наведите указатель на границу между
  столбцами (курсор ↔) и потяните — соседние столбцы делят ширину по-новому; на нижнюю
  границу строки (курсор ↕) — строка становится выше. Двойной щелчок по нижней границе
  строки возвращает высоту по содержимому. В файл пишется стандартная ширина столбцов в
  долях (`colwidth="75*"` у CALS, `relcolwidth` у `simpletable`), а высота — классом
  `outputclass="row-height-15mm"`; публикация HTML, PDF и DOCX переводит их в проценты
  ширины таблицы и минимальную высоту строки. Правки отменяются, как и другие.
- **Изображение** («Вставка → Изображение…») — выбор файла подставляет относительный
  `href`; заготовку атрибута `alt` нужно дополнить осмысленным описанием вручную.
- **Перекрёстная ссылка** («Вставка → Перекрёстная ссылка…») — диалог со списком
  топиков проекта и фильтром по названию.
- **Ключ** (`keyref`) — опишите текст один раз в `keydef` карты, затем ссылайтесь на
  него из любого топика через `<keyword keyref="…"/>` или атрибут `keyref` на пустом
  элементе. Текст подставляется только в пустой элемент — если внутри тега с `keyref`
  уже есть текст, он останется как есть.
- **Сноска** («Вставка → Сноска») — ставит на месте курсора плашку сноски и переводит курсор
  в её строку в области «Сноски» внизу топика с выделенной заготовкой «Текст сноски»:
  набирайте текст сноски сразу, он заменит заготовку. Если перед вставкой выделить текст,
  он станет текстом сноски. Печатается на той же
  странице сайта, где стоит ссылка (не собирается в общий список по всему изданию);
  в DOCX становится настоящей сноской Word, которая печатается на своей физической
  странице автоматически.
- **Термин предметного указателя** — `indexterm` (вложенный `indexterm` — подпункт)
  вставляется через палитру; сам термин в тексте не показывается, а при сборке единого
  HTML-файла и PDF попадает в алфавитный указатель в конце издания.

## Работа с картой публикации

Вкладка **Карта** слева показывает дерево `ditamap`/`bookmap`, выбранной в выпадающем
списке сверху: двойной щелчок открывает топик (и у строки с дочерними тоже — ветка при этом
не сворачивается и не раскрывается; для этого стрелка слева и клавиши `←` / `→`), кнопки
**+ Топик** / **+ Раздел** добавляют ссылку или заголовок раздела, **✕** удаляет выделенную
строку. Правки карты не сбрасывают дерево: раскрытые и свёрнутые ветки и выделенная строка
остаются как были.

Порядок и вложенность элементов карты меняются тремя способами:

- кнопками **↑ / ↓ / → / ←** (переместить, вложить, вынести из вложения);
- перетаскиванием строки мышью — работает только между элементами **одного уровня**
  (одного родителя); перенос в другой родитель делайте кнопками;
- меню **Структура**, если карта открыта как документ.

Разорванные ссылки (файл не найден) подсвечиваются красным.

**Флажок у строки карты** — «публиковать». Снимите его, и топик (вместе со всей веткой под
ним) не попадёт ни в сайт HTML, ни в единый HTML, ни в PDF, ни в DOCX, в том числе в
оглавление и навигацию; в дереве строка становится серой и перечёркнутой. Сам файл и ссылки
на него остаются: ключи и `conref` из исключённого топика по-прежнему работают. По умолчанию
флажок стоит у всех строк. Отдельный топик внутри исключённой ветки можно вернуть, поставив
его флажок снова. В файле карты это стандартный атрибут DITA
`processing-role="resource-only"` (для возвращённого — `processing-role="normal"`); правка,
как и другие правки карты, отменяется и сохраняется вместе с картой. Щелчок по флажку
меняет только его: строка не открывается, ветки не сворачиваются, а окно не переключается
на вкладку карты, даже если карта при этом впервые открылась.

Правая кнопка мыши на строке карты открывает меню:

| Пункт | Что делает |
|---|---|
| Открыть | Открывает топик строки (как двойной щелчок) |
| Свойства… | Открывает карту с выделенной строкой — её атрибуты (`href`, `navtitle`, `toc`…) на панели **Атрибуты** |
| Добавить топик после / перед… | Диалог выбора топика, ссылка встаёт после или перед строкой |
| Добавить дочерний топик… | То же, но ссылка вкладывается в строку последней |
| Добавить раздел | Заголовок раздела без своей страницы (`topichead`) |
| Дублировать | Копия строки (со всеми вложенными) сразу после неё |
| Найти ссылки на топик | Все ссылки проекта на файл строки (карты, `xref`, `conref`, `keydef`) — на вкладке **Поиск** внизу |
| Переименовать / переместить файл… | Как в дереве проекта: файл переносится, ссылки на него обновляются по всему проекту |
| Вырезать, Копировать, Вставить после / перед / как дочерний | Перенос строк внутри карты и между картами (ссылки пересчитываются от папки новой карты) |
| Упорядочить | Вверх, вниз, вложить в предыдущий, вынести на уровень выше |
| Убрать из карты | Удаляет строку карты, файл остаётся |
| Удалить файл… | Удаляет файл топика с диска (после подтверждения, отменить нельзя) и его строки из этой карты; если на файл ссылаются другие документы, об этом предупреждает |
| Развернуть всё, Свернуть всё | Раскрывает или сворачивает дерево карты |

Правки карты из меню, как и кнопками, идут во вкладку карты: они отменяются и сохраняются
как обычные правки документа.

**Таблица соответствий** (кнопка «Таблица соответствий…») — редактор `reltable` карты.
Каждая строка связывает топики из разных столбцов: при публикации они попадают друг
другу в раздел «Смотрите также». Топики одного столбца между собой не связываются. В
ячейке — не больше одного топика (DITA допускает несколько, но в редакторе это не
поддерживается); ячейка может быть пустой.

## Ключи, ключевые слова и предметный указатель

### Зачем ключи

Ключ — имя, за которым скрывается значение: текст, ссылка на топик, адрес сайта или
картинка. Топики ссылаются на имя (`keyref="product"`), а значение задаётся один раз в
карте. Поменялось название продукта или адрес — правится одна строка карты, а не каждый
топик. Ключи также позволяют собрать из тех же топиков разные публикации: каждая карта
задаёт свои значения.

### Как определить ключ

Ключ определяет атрибут `keys` — обычно на элементе `keydef` в карте (подойдёт и любой
`topicref`). Одно определение может задавать несколько имён через пробел.

| Что хранит ключ | Определение в карте | Использование в топике |
|---|---|---|
| Текст (название, версия) | `<keydef keys="product"><topicmeta><keywords><keyword>МойПродукт</keyword></keywords></topicmeta></keydef>` | `<keyword keyref="product"/>`, `<ph keyref="product"/>`, `<uicontrol keyref="…"/>` |
| Ссылку на топик | `<keydef keys="install" href="tasks/install.dita"><topicmeta><navtitle>Установка</navtitle></topicmeta></keydef>` | `<xref keyref="install"/>` — текст ссылки: свой текст внутри `xref`, иначе текст ключа |
| Внешний адрес | `<keydef keys="site" href="https://example.com" scope="external" format="html"><topicmeta><keywords><keyword>сайт продукта</keyword></keywords></topicmeta></keydef>` | `<xref keyref="site"/>` |
| Картинку | `<keydef keys="logo" href="images/logo.png" format="png"/>` | `<image keyref="logo"/>` |
| Термин глоссария | `<keydef keys="plc" href="glossary/plc.dita"/>` | `<abbreviated-form keyref="plc"/>` |
| Общий фрагмент | `<keydef keys="shared" href="reusable/shared.dita"/>` | `<p conkeyref="shared/warning-id"/>` — вставляет элемент с `id="warning-id"` из топика ключа |

Текст ключа берётся из `topicmeta/keywords/keyword`, а если его нет — из
`topicmeta/navtitle`. Если у ключа нет ни того ни другого, пустой `<xref keyref="…"/>`
покажет вместо текста адрес — задайте `navtitle` или напишите текст внутри `xref`.

Правила, о которых стоит помнить:

- **Текст подставляется только в пустой элемент.** `<keyword keyref="product"/>` покажет
  значение ключа, а `<keyword keyref="product">Свой текст</keyword>` — свой текст: так
  требует спецификация DITA. Это удобно для запасного значения на случай, если ключ не
  определён.
- **Первое определение побеждает.** Редактор собирает ключи из всех карт проекта; если
  имя определено дважды, действует первое найденное. Держите ключи в одном месте —
  например, в отдельной карте `keys.ditamap`, подключённой к главной через `mapref`.
- **Ключи пересобираются при сохранении.** Добавили `keydef` — сохраните карту
  (`Ctrl+S`), и ключ появится на вкладке **Ключи** и в предпросмотре.
- **Необъявленный ключ — ошибка проверки.** `F7` находит `keyref` и `conkeyref` на
  несуществующие ключи.

В режиме «Автор» ставить `keyref` удобно на вкладке **Атрибуты**: выделите элемент,
выберите `keyref` в списке «Добавить атрибут» и впишите имя ключа.

### Области ключей (`keyscope`)

Атрибут `keyscope` на `topicref`/`topichead` создаёт для ветки свою
область ключей. Внутри неё ключ ищется сначала в своей области, потом в родительских,
вплоть до корня. Так в одной публикации можно описать две модели устройства: в ветке
`keyscope="basic"` ключ `model` означает «Базовая», в ветке `keyscope="pro"` — «Про», а
топики используют один и тот же `keyref="model"`.

К ключу конкретной области можно обратиться явно: `keyref="pro.model"`.

Вкладка **Ключи** показывает только ключи корневой области; подсказка под списком
сообщает, сколько ключей находится внутри областей.

### Проекты-источники ключей

Если общие ключи (название продукта, версия, общие фрагменты) живут в отдельном
проекте, подключите его: **Файл → Подключить проект-источник ключей…**. Карты
проекта-источника не публикуются вместе с текущим проектом, но `keyref`/`conkeyref` на
ключ, которого нет в своём проекте, ищется и там. Связь сохраняется вместе с проектом;
**Файл → Отключить все проекты-источники** её снимает. Ключи подключённых проектов в
списке вкладки не показываются.

### Ключевые слова (`keywords`)

Слово «ключевые» в DITA встречается в двух разных смыслах — не путайте их:

- `keyword` внутри **определения ключа** (`keydef/topicmeta/keywords/keyword`) — это
  *значение* ключа, текст для подстановки (см. выше);
- `keywords` в **прологе топика** (`prolog/metadata/keywords`) — это *метаданные*: слова,
  описывающие содержание топика, для поиска и каталогизации. В текст публикации они не
  выводятся.

```xml
<prolog>
  <metadata>
    <keywords>
      <keyword>резервная копия</keyword>
      <keyword>восстановление</keyword>
    </keywords>
  </metadata>
</prolog>
```

Внутри текста элемент `keyword` без `keyref` просто помечает слово как ключевое понятие
(имя продукта, термин) и выводится как обычный текст.

### Предметный указатель (`indexterm`)

Термин указателя ставится прямо в текст топика или в `prolog/metadata/keywords`:

```xml
<p><indexterm>резервная копия</indexterm>Программа сохраняет копию…</p>
<indexterm>резервная копия<indexterm>восстановление</indexterm></indexterm>
```

Вложенный `indexterm` — подпункт указателя. Алфавитный указатель собирается при
публикации **единого HTML-файла** (и в PDF, который из него печатается); в многостраничном
сайте и в DOCX `indexterm` не выводится.

## Рефакторинг: id, файлы, conref

- **Переименовать id** («Структура → Переименовать id…») — поставьте курсор в элемент с
  `id` и введите новое значение: все `href`/`conref` в проекте, указывающие на этот `id`,
  обновятся. `keyref`/`conkeyref` не трогаются — они ссылаются на ключ, а не на `id`.
  Если у элемента нет `id`, сначала задайте его на вкладке «Атрибуты».
- **Переименовать / переместить файл** — правый клик по файлу на вкладке «Проект».
  Файл переносится на диске (папка назначения создаётся при необходимости), его
  собственные относительные ссылки пересчитываются, входящие ссылки из остальных
  файлов проекта обновляются.
- **Вынести в conref** («Структура → Вынести в conref…») — содержимое текущего элемента
  переносится в существующий топик или в новый файл (по умолчанию предлагается
  `reusable/shared.dita`), а на исходном месте остаётся пустой элемент со ссылкой
  `conref`. Текст дальше правится в целевом топике.

Изменённые рефакторингом документы помечаются как несохранённые — проверьте результат и
сохраните (`Ctrl+Shift+S`). Перенесённый файл и новый файл для conref записываются на
диск сразу.

## Проверка и поиск

**F7** (или «Правка → Проверить проект») проверяет сразу все файлы: соответствие
контент-модели, допустимые атрибуты и значения перечислений, повторяющиеся `id`,
редакторские рекомендации (пустой заголовок/шаг, отсутствующий `shortdesc`, изображение
без `href`/`keyref` или без `alt`), битые перекрёстные и key-ссылки, а также правила из
подключённых плагинов. Список замечаний — на вкладке «Проверка» внизу, двойной щелчок
переходит к месту. «Правка → Проверить документ» — то же самое для одного открытого файла.

**Ctrl+Shift+F** (или «Правка → Найти в проекте…») открывает вкладку «Поиск»:

- обычный текст или, если отметить галочку «регулярное выражение», поиск по regex
  (синтаксис .NET);
- галочка «искать имена элементов» ищет по именам тегов вместо текста;
- второе поле и кнопка **«Заменить всё»** заменяют найденное сразу во всех файлах
  проекта (недоступно при поиске по именам элементов). Замена работает по отдельным
  текстовым узлам и не пересекает границу с вложенными элементами (например, если
  часть фразы оформлена полужирным). Изменённые документы помечаются как
  несохранённые — сохраните их (`Ctrl+Shift+S`) после проверки результата.

## Рецензирование и сравнение версий

**Пометка изменений (`rev`).** «Структура → Отметить как изменённое (rev)» ставит на
текущий элемент `rev="changed"` (повторный вызов снимает пометку). При публикации у
таких элементов появляется полоса на полях.

**Track changes.** Пункты меню «Структура → Track changes: …» работают со штатными
атрибутами DITA:

- «пометить как вставленное» — `status="new"`; элемент подсвечивается в предпросмотре и
  остаётся в публикации;
- «пометить как удалённое» — `status="deleted"`; элемент остаётся в документе
  (зачёркнутым в предпросмотре), но из публикации исключается сразу;
- «принять правку» — вставка остаётся без пометки, удалённый элемент убирается из
  документа;
- «отклонить правку» — вставленный элемент убирается, удалённый восстанавливается.

Вместе с пометкой записываются автор (имя пользователя в системе) и дата — атрибуты
`tcauthor` и `tcdate`.

**Сравнение файлов.** «Правка → Сравнить файлы…» — выберите два файла, различия
показываются построчно, как в обычном diff (различия форматирования тоже видны).
Кнопки **→** / **←** у группы различий переносят её в другой файл и **сразу
записывают файл на диск**.

**Сравнение с git / SVN.** «Правка → Сравнить с последним коммитом (git)» и «Сравнить с
версией BASE (svn)» открывают то же окно сравнения: слева — версия из истории, справа —
файл на диске. Нужен установленный `git` или `svn` в `PATH`, файл должен быть под
версионным контролем. Версия BASE в SVN — последняя полученная при обновлении рабочей
копии, сеть для неё не нужна.

Сравнение читает файлы с диска: несохранённые правки открытой вкладки в нём не видны —
сохраните документ перед сравнением.

## Предпросмотр

Подрежим **Предпросмотр** документа показывает результат публикации с уже
подставленными `conref` и `keyref`. Выпадающий список над ним выбирает вид:

- **HTML** — как страница сайта;
- **PDF** — документ действительно печатается в PDF во временный файл (с колонтитулами
  проекта, если они включены), поэтому видна настоящая разбивка на страницы;
- **DOCX (приближённо)** — HTML со стилем, подобранным под экспорт в Word (чёрные
  жирные заголовки, примечания серой полосой); структура похожа, но это не
  пиксель-в-пиксель.

Кнопка «Обновить» перестраивает предпросмотр, «Открыть внешним приложением» открывает
результат в браузере или программе просмотра PDF.

Предпросмотр показывает встроенный браузер (Chromium) — отдельно ставить ничего не нужно.
Он запускается при первом открытии предпросмотра, поэтому первый показ занимает пару
секунд. Если встроенный браузер запустить не удалось (например, в Linux нет нужных
системных библиотек), вкладка сообщает причину и предлагает открыть построенный файл
внешним приложением. В легаси-версии WPF предпросмотр показывает WebView2.

## Публикация: HTML, PDF, DOCX

Все способы собирают выбранную карту (вкладка «Карта» должна показывать нужную карту в
выпадающем списке сверху). Перед сборкой несохранённые документы сохраняются
автоматически, а пространство ключей пересобирается.

**HTML.** «Публикация → Собрать сайт HTML…» (`F5`) — многостраничный сайт с оглавлением
и постраничной навигацией; «Собрать один HTML…» — всё содержимое карты в одном файле
(удобно для печати) с алфавитным предметным указателем в конце. Картинки копируются в
папку `media` рядом с результатом. Подключить свои стили — «Публикация →
Пользовательский CSS…»: можно создать новый файл (с готовыми классами для разрывов
страниц, см. ниже) или подключить существующий; путь сохраняется вместе с проектом.

**PDF.** «Публикация → Экспорт в PDF…» печатает единый HTML-файл. Без колонтитулов PDF
печатается установленным Edge/Chrome в фоновом режиме, а если его нет — встроенным
браузером. Чтобы включить колонтитулы или задать свой текст шапки/подвала — «Публикация →
Колонтитулы PDF…»: тогда печатает встроенный браузер — текст шапки по центру, текст подвала
слева и «стр. N из M» справа. Если встроенный браузер недоступен, PDF печатается
установленным Edge/Chrome, но уже без своих колонтитулов (об этом пишет журнал сборки). В
легаси-версии WPF вместо встроенного браузера печатает WebView2.

**DOCX.** «Публикация → Экспорт в DOCX…» собирает карту в один файл Word напрямую в
OOXML (не через конвертацию HTML): настоящее оглавление — поле TOC, сразу заполненное
строками-ссылками на топики по уровням (видно в любой программе, щелчок ведёт к разделу),
Word при открытии пересобирает его с номерами страниц; настоящие сноски (Word сам кладёт
каждую на нужную физическую страницу), CALS-таблицы с объединением ячеек, разрывы страниц — теми же токенами
`outputclass`, что и в HTML/PDF (см. ниже). SVG-изображения Word не поддерживает
напрямую — вместо картинки в текст попадает плашка с именем файла и предупреждение в
журнале сборки; PNG/JPEG/GIF/BMP/TIFF встраиваются как обычно. Шрифты, цвета и отступы
берутся из того же пользовательского CSS, титул, оглавление, нумерация заголовков и
колонтитулы — из «Публикация → Оформление DOCX…», подробнее — в разделе
[«Оформление DOCX»](#оформление-docx-css-и-настройки-word).

**Формат из плагина.** «Публикация → Публикация плагином…» — если в папке `plugins`
есть плагины форматов публикации, выберите нужный из списка (см. [Плагины](#плагины)).

**Параметры страницы** (общее для PDF и DOCX) — «Публикация → Параметры страницы…»:
размер бумаги (A4, A3, A5, B5, Letter, Legal), ориентация (книжная или альбомная) и
поля сверху, снизу, слева и справа в миллиметрах. Схема листа в диалоге сразу показывает,
что получится. Пустое поле или «Как в CSS проекта» — значение из правила `@page`
пользовательского CSS (а без него — A4 с полями 20 мм); заданное в диалоге главнее CSS.
Настройки хранятся в проекте (файл `.ditastudio-docx`).

**Разрывы страниц и перенос таблиц** (общее для PDF и DOCX) задаются через атрибут
`outputclass` в панели «Атрибуты» или пунктами меню «Структура»:

- `page-break-before` на `title` — начинает новую страницу печати;
- `nonumber` на `title` — **заголовок без номера**: при публикации он не нумеруется и не
  попадает в оглавление (DOCX, единый HTML, PDF). Ставится без атрибутов: курсор в
  заголовок → правая кнопка мыши → «Заголовок без номера (не в оглавлении)» или меню
  «Структура»; в «Авторе» у такого заголовка справа пометка «без номера · не в
  оглавлении». Тот же эффект для целой ветки карты — стандартный атрибут `toc="no"` у
  строки карты (панель «Атрибуты» после «Свойства…» в меню строки);
- `page-break-auto` на `table` — разрешает таблице переноситься между страницами
  (с повтором строки заголовка); без этого класса таблица печатается как единый блок.

Итог сборки и предупреждения (битые ссылки, пропущенные картинки) — на вкладке «Журнал
сборки» внизу.

## Оформление DOCX: CSS и настройки Word

Оформление документа Word задаётся двумя способами, которые дополняют друг друга:

- **внешний вид текста** — тем же пользовательским CSS, что и для HTML и PDF
  («Публикация → Пользовательский CSS…»);
- **устройство документа**, которое CSS описать не может, — диалогом
  **«Публикация → Оформление DOCX…»**: титульная страница, оглавление, нумерация
  заголовков, колонтитулы, переплёт; размер бумаги, ориентация и поля — диалогом
  **«Публикация → Параметры страницы…»** (он же действует на PDF).

### Как CSS попадает в Word

Экспорт больше не форматирует текст напрямую: каждому виду содержимого соответствует
**именованный стиль Word**, а правила CSS меняют эти стили. Поэтому документ можно
дорабатывать и в самом Word — «Главная → Стили» покажет те же стили, и изменение стиля
разом меняет весь документ.

| Селектор CSS | Стиль Word |
|---|---|
| `body`, `html`, `:root` | «Обычный» (Normal) — база для всех стилей; берутся только свойства текста: шрифт, размер, цвет, межстрочный интервал |
| `p` | «Основной текст» (Body Text) — абзацы; здесь работают и поля, и выравнивание |
| `h1` … `h6` | «Заголовок 1…6» |
| `.shortdesc` | «Краткое описание» |
| `.note`; `.note.tip`, `.note.important`, `.note.warning` (и `caution`, `attention`, `notice`), `.note.danger` | «Примечание» и его варианты по типу; `.note .label` — метка «Примечание:» |
| `pre`, `.codeblock` | «Блок кода» |
| `code`, `.codeph`, `.filepath`, `.parmname`… | «Код в тексте» (символьный) |
| `.uicontrol`, `.wintitle` | «Элемент интерфейса» (символьный) |
| `.term` | «Термин» (символьный) |
| `a`, `.xref` | «Hyperlink» (символьный) |
| `li` | «Элемент списка»; `.cmd` — «Команда шага»; `.info`, `.stepresult` — «Пояснение к шагу» |
| `ul`, `ul ul`, `li::marker` | маркеры списков по уровням и их цвет (см. ниже) |
| `dt`, `dd` | «Термин списка», «Определение» |
| `blockquote`, `.lq` | «Цитата» |
| `.fig-title`, `.table-title` | подписи рисунков и таблиц |
| `table`, `th`, `td` | рамки таблицы и ячеек, заливка шапки и строк, поля ячеек; шрифт — стили «Текст таблицы» и «Шапка таблицы» |
| `.related-links`, `.draft-comment`, `.rev-changed`, `.fn` | «Смотрите также», черновые комментарии, полоса изменений, текст сносок |
| `.doc-title`, `.doc-subtitle`, `.doc-author`, `.doc-toc-title`, `.doc-header`, `.doc-footer` | титул, заголовок оглавления и колонтитулы — есть только в DOCX |

Селектор вида `p.shortdesc` работает так же, как `.shortdesc`: теги HTML и Word
соотносятся не один к одному. Правила применяются по обычному каскаду CSS — более
специфичный селектор побеждает, при равной специфичности побеждает правило ниже по файлу.

**Свои классы.** Правило для класса, которого нет в таблице, применяется к элементам с
таким значением `outputclass` — и к элементам DITA с таким именем (`.keyword { … }`
оформит все `keyword`). Для каждого сочетания экспорт создаёт производный стиль, например
«Основной текст · warning-box»: он основан на обычном стиле абзаца и добавляет оформление
класса. Класс на блоке (`section`, `note`, весь топик) оформляет все абзацы внутри, класс
на фразовом элементе (`ph`, `keyword`) — только его текст.

**Какие свойства переносятся:** `font-family`, `font-size`, `font-weight`, `font-style`,
`font` (краткая запись), `color`, `background`/`background-color`, `text-decoration`,
`text-transform: uppercase`, `font-variant: small-caps`, `letter-spacing`, `vertical-align:
super|sub`, `text-align`, `text-indent`, `line-height`, `margin*`, `padding*`, `border*`
(толщина, стиль, цвет по сторонам), `page-break-before/after/inside` и `break-*`,
`display: none` и `visibility: hidden` (скрытый текст). Работают переменные CSS
(`var(--accent)`), объявленные в `:root`, `html` или `body`. Единицы — `px`, `pt`, `em`,
`rem`, `%`, `mm`, `cm`, `in`.

`padding` у стороны с рамкой становится расстоянием от текста до рамки, без рамки —
прибавкой к отступу или интервалу. Поля и фон `body` к абзацам не применяются, иначе
каждый абзац документа получил бы рамку веб-страницы.

**Маркеры списков** задаются так же, как для сайта:

```css
ul { list-style-type: square; }        /* ■ — первый уровень и глубже */
ul ul { list-style-type: "–"; }        /* тире со второго уровня */
li::marker { color: #1a5fb4; }         /* цвет маркеров и номеров */
.dash { list-style-type: "—"; }        /* списки с outputclass="dash" */
.sl { list-style: none; }              /* простые списки sl — без маркеров */
```

Поддерживаются `disc`, `circle`, `square`, `none` и любой текст в кавычках — он рисуется
шрифтом абзаца. `ul ul` действует на второй уровень и глубже, `ul ul ul` — на третий.
В `li::marker` работают `color` и `content` (текст маркера). Вид нумерации `ol`
(`lower-alpha`, `upper-roman`) и картинки-маркеры (`url(…)`) в Word пока не переносятся —
о них будет предупреждение в журнале сборки.

**Размер и поля страницы** — правилом `@page`:

```css
@page { size: A4; margin: 20mm 15mm 20mm 25mm; }
@page { size: A5 landscape; }
```

Поддерживаются форматы A3–A6, B4, B5, letter, legal и явные размеры (`210mm 297mm`).

**Правила только для Word.** Блок `@media docx { … }` применяется при экспорте в DOCX,
а браузер его пропускает. `@media print` действует и на PDF, и на DOCX; `@media screen` и
запросы с условиями (`(max-width: …)`) к Word не относятся.

```css
/* сайт и PDF — одинаково, в Word — крупнее и с полями под переплёт */
@media docx {
  body { font-size: 12pt; }
  h1 { page-break-before: always; }
}
```

**Что не переносится** — и попадает предупреждением в «Журнал сборки»: скругления и тени
(`border-radius`, `box-shadow`), картинки и градиенты в фоне, `text-transform: capitalize`,
составные селекторы, которых нет в таблице выше (`#id`, `.a .b` для своих классов,
`:first-child`). Свойства вёрстки веб-страницы (`width`, `display: flex`, `position`…)
и состояния вроде `:hover` пропускаются молча. `@font-face` не встраивает шрифт в
документ: шрифт должен быть установлен там, где документ открывают.

### Настройки «Оформление DOCX»

«Публикация → Оформление DOCX…» — то, что не выражается через CSS. Настройки сохраняются
вместе с проектом (файл `.ditastudio-docx`) и применяются при каждом экспорте.

- **Титульная страница** — название карты, подзаголовок, автор или организация, дата
  публикации. Автор записывается и в свойства файла Word.
- **Оглавление** — включить или выключить, сколько уровней заголовков в нём показывать
  (по умолчанию 3) и как оно называется: «Содержание», «Оглавление» или свой текст
  (название действует и на оглавление единого HTML и PDF).
- **Нумерация заголовков** — «1», «1.1», «1.1.1» до выбранного уровня; номера видны и в
  оглавлении. Действует и на единый HTML, PDF и сайт, а нумерованные абзацы получают номер
  следующего уровня (2.3.1).
- **Каждый топик верхнего уровня с новой страницы.**
- **Нумерация рисунков и таблиц** в подписях.
- **Колонтитулы** — текст и выравнивание верхнего и нижнего колонтитула. Поля:
  `{page}` — номер страницы, `{pages}` — число страниц, `{title}` — название карты,
  `{date}` — дата публикации. Например: `Стр. {page} из {pages}`. Флажок «Не показывать
  на первой странице» убирает колонтитулы с титула. **Картинка** (например, логотип; PNG,
  JPEG, GIF, BMP) — кнопка «Обзор…» у верхнего или нижнего колонтитула: место (слева, по
  центру, справа) и высота в миллиметрах, ширина — по пропорциям. Если место картинки и
  текста совпадает, они стоят рядом. Картинка попадает и в колонтитулы PDF (когда они
  включены в «Колонтитулы PDF…»); путь хранится относительно папки проекта.
- **Печать** — зеркальные поля для двусторонней печати и поле переплёта в миллиметрах.
- **Язык текста** (для проверки правописания в Word) и **автоматическая расстановка
  переносов**.

Размер страницы и поля в диалоге не задаются — они в CSS (`@page`), чтобы HTML-печать,
PDF и DOCX не расходились.

## Условия сборки и .ditaval

Одно и то же содержимое можно собирать по-разному в зависимости от атрибутов `props`,
`platform`, `product`, `audience`, `otherprops` и `deliveryTarget`. Есть два способа
задать условия; они складываются.

**Условия в диалоге.** «Публикация → Условия сборки…» сканирует проект и строит список
фактически использованных значений условных атрибутов — отметьте, что нужно исключить
из сборки, и при необходимости включите показ черновых комментариев (`draft-comment`).
Условия сохраняются вместе с проектом и применяются при каждой сборке.

**Связанный файл `.ditaval`.** «Публикация → Подключить .ditaval…» привязывает к проекту
стандартный файл DITAVAL (например, из другого инструмента). Файл не копируется, а
перечитывается при каждой сборке: правки, сделанные в нём снаружи, подхватываются без
повторного подключения. Поддерживаются правила:

- `action="exclude"` — исключить элементы с этим значением атрибута;
- `action="flag"` — подсветить их в публикации: цвет текста, фон, начертание, полоса
  изменений.

`include` и `passthrough` пропускаются.

«Публикация → Редактировать .ditaval…» правит правила исключения связанного файла прямо
в приложении: диалог показывает значения условных атрибутов из проекта, отмеченные
записываются обратно в тот же файл. Правила подсветки при этом сохраняются как были.

## Перевод через XLIFF

1. Откройте топик и выберите «Публикация → Экспорт в XLIFF (для перевода)…». Каждый
   блочный элемент с текстом (заголовок, краткое описание, абзац, пункт списка…)
   становится отдельным сегментом; фразовая разметка внутри — тегами `bpt`/`ept`
   (переводчик видит и переводит текст внутри них) или `ph` (изображение, ссылка без
   текста).
2. Передайте файл переводчику или загрузите в CAT-инструмент; перевод записывается в
   элементы `target`.
3. Откройте тот же топик и выберите «Публикация → Импортировать перевод из XLIFF…».
   Текст из `target` подставится на место исходного; строка состояния покажет, сколько
   сегментов применено.

Сегменты сопоставляются с документом по порядку обхода, поэтому **не меняйте структуру
топика между экспортом и импортом**. Если структура разошлась, несовпавшие сегменты
пропускаются и перечисляются в предупреждениях, остальной перевод всё равно применяется.
Экспорт — по одному документу; пара языков в файле — `ru` → `en`.

## Собственные специализации: внешний DTD

Если в проекте используются свои элементы (специализации DITA), подключите их DTD:
**Файл → Подключить внешний DTD (кастомная специализация)…**. Редактор разбирает
настоящий DTD-синтаксис — объявления `ENTITY`, `ELEMENT`, `ATTLIST`, параметрические
сущности, подключаемые модули `SYSTEM`/`PUBLIC` — и добавляет элементы в каталог. После
этого они работают как встроенные: в палитре вставки, автодополнении, проверке и
публикации. Способ отображения элемента выводится из его `@class` (от какого базового
элемента он специализирован).

Связь с DTD сохраняется вместе с проектом и восстанавливается при каждом открытии и
обновлении проекта; «Файл → Отключить внешний DTD» её снимает.

Элементы DTD действуют только в своём проекте: при открытии другого проекта редактор
переключается на его собственный каталог, так что проекты с конфликтующими
специализациями не мешают друг другу. После правки самого `.dtd` выполните
«Обновить проект» — DTD перечитается. Отключение DTD сразу убирает его элементы.

## Плагины

Плагины — это `.dll` в папке `plugins` рядом с исполняемым файлом редактора (папка
создаётся при первом запуске); один и тот же плагин работает в обеих версиях. Они загружаются один раз при старте редактора. Три вида:

- **правила проверки** — дополнительные замечания в «Проверить проект»
  (контракт `IValidationRulePlugin` из `DitaStudio.Core`);
- **форматы публикации** — пункт «Публикация → Публикация плагином…»
  (`IPublishFormatPlugin` из `DitaStudio.Core`);
- **команды режима «Автор»** — пункт «Структура → Команда плагина…»
  (`IAuthorCommandPlugin` из `DitaStudio.Presentation`).

Если плагинов одного вида несколько, редактор предлагает выбрать нужный из списка.
Ошибка внутри плагина не закрывает редактор — она показывается как предупреждение.
Пример плагина с правилами проверки — `tests/TestPlugin`: проект ссылается на
`DitaStudio.Core.dll` без копирования её в свой вывод (`Private=false`).

## Оформление

«Справка → Тёмная тема» переключает светлую и тёмную тему; выбор запоминается между
запусками.

## Сохранность правок

**Надёжное сохранение.** Файл сначала пишется во временный файл в той же папке
(`.~dita-….tmp`) и только потом заменяет оригинал. Если в этот момент пропадёт питание
или кончится место на диске, на диске останется прежняя версия, а не обрезанная новая.

**Восстановление после сбоя.** Каждые 30 секунд редактор копирует текст вкладок с
несохранёнными правками (помечены «•») в папку данных программы — `%LOCALAPPDATA%\DitaStudio\Recovery`
в Windows, `~/.local/share/DitaStudio/Recovery` в Linux,
`~/Library/Application Support/DitaStudio/Recovery` в macOS — сами
файлы проекта при этом не меняются. Копия удаляется, когда документ сохранён или вы
отказались от правок при закрытии. Если редактор завершился аварийно, при следующем
открытии того же проекта появится окно «Восстановление после сбоя» со списком документов:

- **Да** — документы откроются с восстановленными правками; они ещё не сохранены —
  проверьте и нажмите `Ctrl+S`;
- **Нет** — копии удаляются;
- **Отмена** — решить позже, копии предложат снова при следующем открытии проекта.

Пометка «файл с тех пор менялся» значит, что оригинал успели изменить после снятия копии
(например, git pull) — сравните версии перед сохранением.

**Файл изменён другой программой.** Редактор следит за файлами открытых вкладок:

- вкладка без несохранённых правок перечитывается сама, в строке состояния появляется
  «перечитан с диска»;
- если во вкладке есть правки, редактор спросит: **Да** — загрузить версию с диска (свою
  можно вернуть через «Правка → Отменить структурное изменение», `Ctrl+Alt+Z`),
  **Нет** — оставить свою, при сохранении она заменит файл на диске;
- если файл удалили или переименовали, вкладка остаётся открытой и помечается
  несохранённой — `Ctrl+S` запишет его заново.

**Смена проекта и выход** сначала предлагают сохранить изменения. Если сохранить не
удалось (например, файл только для чтения), окно не закроется и проект не сменится.
