# DITA Studio

Настольный редактор технической документации на DITA 1.3 — аналог Oxygen XML Author,
написанный на C# (WPF, .NET 8). Ядро (`DitaStudio.Core`) не имеет ни одной внешней
зависимости; во внешних библиотеках нуждаются только интерфейс (AvalonEdit, WebView2,
CommunityToolkit.Mvvm) и экспорт в Word (`DitaStudio.Docx` → DocumentFormat.OpenXml).

Готовая сборка для Windows x64 (не требует установленного .NET) — на странице
[релизов](https://github.com/Saratiga/DitaStudio/releases). Для предпросмотра и печати в
PDF нужен WebView2 Evergreen Runtime (на Windows 11 он обычно уже установлен).

## Что умеет

**Режим «Автор»** — визуальное редактирование, как в текстовом процессоре, но каждая
правка сразу попадает в дерево DITA и проверяется по контент-модели — получить
невалидный документ через этот режим нельзя:

- текст правится прямо в оформленном виде; фразовые элементы (`b`, `codeph`, `uicontrol`,
  `filepath`, `term`…) показываются оформлением, а не тегами;
- `Enter` создаёт следующий абзац, пункт списка или шаг задачи; `Backspace` в начале блока
  объединяет его с предыдущим; `Tab` / `Shift+Tab` меняют уровень вложенности пункта;
- `Ctrl+B`, `Ctrl+I`, `Ctrl+U`, `Ctrl+\``, `Ctrl+Shift+U` оборачивают выделение в `b`, `i`,
  `u`, `codeph`, `uicontrol`;
- ссылки, изображения, сноски и элементы с `conref` показываются компактными плашками;
  сноска (`fn`) вставляется через «Вставка → Сноска» и печатается на той же странице
  сайта, где стоит ссылка на неё, а в DOCX — как настоящая сноска Word;
- таблицы CALS, `simpletable`, `properties` и `choicetable` редактируются по ячейкам,
  включая объединение по горизонтали и вертикали (`Ctrl+Alt+→` / `Ctrl+Alt+↓`);
- работает проверка орфографии (встроенная, `ru-RU`);
- слева от блоков видны имена элементов (можно выключить в меню «Структура»).

**Режим «Исходный код»** — подсветка синтаксиса, автодополнение элементов и атрибутов
по каталогу DITA (`Ctrl+Пробел`), переход к строке из панели проверки. Переключение между
режимами синхронизирует модель в обе стороны.

**Режим «Предпросмотр»** — топик с разрешёнными `conref` и `keyref` в одном из трёх видов:
HTML, PDF (настоящая печать с реальной разбивкой на страницы) или DOCX (приближённо —
HTML со стилем, подобранным под экспорт в Word). Кнопка «Открыть внешним приложением»
показывает тот же результат в браузере или программе просмотра PDF.

**Карты публикации** — дерево `ditamap` / `bookmap` с раскрытием вложенных карт, добавлением
топиков и разделов; порядок и вложенность меняются кнопками или перетаскиванием; подсветка
битых ссылок; редактор таблицы соответствий (`reltable` → «Смотрите также»); области
ключей (`keyscope`) — разные значения одного ключа в разных ветках карты.

**Проверка** — по контент-моделям DITA, а не «на глазок»:

- допустимость и порядок дочерних элементов (сообщение подсказывает, что здесь уместно);
- обязательные атрибуты и значения перечислений;
- уникальность `@id`, битые `href` / `conref` / `conkeyref`, необъявленные ключи;
- редакторские замечания: пустой заголовок, отсутствующий `shortdesc`, картинка без `alt`;
- дополнительные правила из плагинов.

**Поиск по проекту** — обычный текст или регулярное выражение (.NET), поиск по именам
элементов, замена всех вхождений сразу по всему проекту.

**Рефакторинг** — переименование `id` и перенос/переименование файла с обновлением всех
`href`/`conref` в проекте; вынесение элемента в `conref` (в существующий топик или новый файл).

**Рецензирование** — пометка изменений атрибутом `rev` (полоса на полях при публикации),
track changes через штатный `status="new"/"deleted"` с автором и датой (принять/отклонить),
сравнение двух файлов с построчным переносом различий, сравнение открытого документа с
последним коммитом git или с версией BASE в SVN.

**Публикация** — HTML-сайт с оглавлением и постраничной навигацией, единый HTML-файл
с алфавитным предметным указателем (`indexterm`), **экспорт в DOCX** (нативная сборка в
OOXML, а не конвертация HTML: настоящие сноски Word, поле оглавления, объединение ячеек
таблиц, разрывы страниц), экспорт в PDF (печать через Edge/Chrome или WebView2 — WebView2
также умеет печатать со своими колонтитулами), подключаемый пользовательский CSS.

**Условная сборка** — исключение содержимого по `props` / `platform` / `product` /
`audience` / `otherprops` / `deliveryTarget`: через диалог или через связанный с проектом
файл `.ditaval` (правила `exclude` и `flag` — подсветка цветом, фоном, начертанием, полосой
изменений). Файл перечитывается при каждой сборке и редактируется прямо из приложения.

**Перевод** — экспорт открытого топика в XLIFF 1.2 (фразовая разметка — как `bpt`/`ept`/`ph`)
и импорт готового перевода обратно в документ.

**Проект** — восемь последних открытых папок в «Файл → Недавние проекты»; подключение
других проектов как источников ключей (`keyref`/`conref` ищутся и там); подключение
внешнего DTD с собственными специализациями; пересборка пространства ключей при сохранении.

**Расширяемость** — плагины (.dll в папке `plugins` рядом с exe): свои правила проверки,
свои форматы публикации, свои команды режима «Автор».

**Оформление** — светлая и тёмная тема («Справка → Тёмная тема», выбор запоминается).

## Охват DITA 1.3

Каталог элементов задаётся текстовым описанием в `src/DitaStudio.Core/Schema/CatalogSource*.cs`
в синтаксисе, близком к DTD (параметрические сущности, контент-модели, списки атрибутов):

- базовый модуль `topic` со всеми блочными и фразовыми элементами;
- специализации `concept`, `task` (строгая и общая), `reference`, `troubleshooting`,
  `glossentry`, `glossgroup`;
- таблицы CALS, `simpletable`, `properties`, `choicetable`;
- пролог и метаданные;
- домены `hi-d`, `pr-d`, `sw-d`, `ui-d`, `ut-d`, `markup-d`/`xml-d`, `hazard-d`,
  `equation-d`, `svg-d`, `mathml-d`, `abbrev-d`, `indexing-d`, `release-management`;
- карты: `map`, `bookmap`, `subjectScheme`, `mapgroup-d`, `ditavalref-d`;
- модуль обучения: `learningBase`, `learningOverview`, `learningContent`, `learningSummary`,
  `learningAssessment`, `learningPlan` и интерактивные задания.

Каталог легко расширять: добавьте строку вида

```
имя :: @class :: отображение :: контент-модель :: атрибуты :: описание
```

и элемент сразу появится в палитре вставки, автодополнении, валидаторе и генераторах
HTML/DOCX. Собственные специализации можно не описывать вручную, а подключить готовым
DTD: «Файл → Подключить внешний DTD…» разбирает настоящий DTD-синтаксис (`ENTITY`,
`ELEMENT`, `ATTLIST`, параметрические сущности, подключаемые модули) и вливает элементы
в тот же каталог.

## Сборка и запуск

Нужен **.NET SDK 8.0** (проверить: `dotnet --version`).

```powershell
dotnet build DitaStudio.sln -c Release
dotnet run --project src\DitaStudio.App
```

Готовый исполняемый файл после сборки: `src\DitaStudio.App\bin\Release\net8.0-windows\DitaStudio.exe`.

Самодостаточная сборка без установленного .NET (так собирается архив для релиза):

```powershell
dotnet publish src\DitaStudio.App -c Release -r win-x64 --self-contained true -o publish
```

## Тесты

```powershell
dotnet run --project tests\DitaStudio.Tests   # 697 проверок ядра и DOCX-экспорта
dotnet test tests\DitaStudio.UiTests          # UI-тесты на реальном DitaStudio.exe
```

Проверки ядра — обычная консольная программа без xunit: код возврата 0 означает, что всё
прошло. Помимо примеров там есть property-based проверки (контент-модели, DTD, XLIFF,
`.ditaval`) со случайными входными данными на фиксированном зерне.

UI-тесты (xUnit + FlaUI) запускают собранный `DitaStudio.exe` и управляют им через UI
Automation, поэтому решение нужно собрать заранее. Та же библиотека управления доступна
из командной строки для ручной проверки: `dotnet run --project tools\UiHarness -- --help`.

Полный чек-лист функционального тестирования — [docs/TESTPLAN.md](docs/TESTPLAN.md).

## С чего начать

1. **Файл → Открыть папку проекта** и выберите `samples\DitaStudioGuide` — руководство
   пользователя по самому DITA Studio, оформленное как DITA-проект (заодно демонстрирует
   сноски, разрывы страниц и объединение ячеек). Для более простого учебного примера —
   `samples\GuideSample`; для реального крупного проекта — `samples\CE207R7`.
2. Вкладка **Карта** слева — дерево публикации; двойной щелчок открывает топик,
   перетаскивание меняет порядок.
3. **F7** — проверить проект, **F5** — собрать HTML-сайт.
4. Панель **Вставка** справа показывает только те элементы, которые допустимы
   в текущей позиции; двойной щелчок вставляет элемент.
5. **F1** — справка по элементу под курсором: контент-модель, атрибуты, модуль.

Подробный разбор всех возможностей — в [USAGE.md](USAGE.md).

операции (вставку, удаление, перемещение, правку исходного кода).

```

  Model/                        DOM: узлы, документ, сериализация
  Schema/                       каталог DITA 1.3, разбор контент-моделей, автомат допустимости
  Schema/Dtd/                   чтение внешних DTD (кастомные специализации)
  Validation/                   проверка структуры, атрибутов, стиля
  Project/                      папка проекта, ditamap, ключи, conref/keyref, поиск/замена,
                                .ditaval, рефакторинг
  Publishing/                   генератор HTML, подписи, стили, печать в PDF
  Editing/                      структурные операции, история отмены, track changes
  Diff/                         построчное сравнение, чтение версий из git/SVN
  Localization/                 экспорт/импорт XLIFF 1.2
  Plugins/                      загрузчик плагинов
  Templates/                    заготовки новых документов
src/DitaStudio.Docx/            нативный рендерер DITA → OOXML (DocumentFormat.OpenXml)
src/DitaStudio.App/             интерфейс WPF (MVVM на CommunityToolkit.Mvvm)
  Authoring/                    режим «Автор», редактор строки, редактор исходного кода
  ViewModels/                   модели представления главного окна по областям
  Views/                        вкладка документа, диалоги, окно сравнения
  Plugins/                      контракт команд «Автора» и реестр плагинов
tests/DitaStudio.Tests/         проверки ядра и DOCX-экспорта (консольная программа)
tests/DitaStudio.UiTests/       UI-тесты (xUnit + FlaUI)
tests/TestPlugin/               пример плагина
tools/DitaStudio.UiAutomation/  общая библиотека UI-автоматизации (FlaUI/UIA3)
tools/UiHarness/                CLI для ручной UI-проверки
samples/GuideSample/            небольшой учебный DITA-проект
samples/DitaStudioGuide/        руководство пользователя по DITA Studio, оформленное как DITA-проект
samples/CE207R7/                крупный реальный проект (техническое руководство на счётчик)
docs/TESTPLAN.md                чек-лист функционального тестирования
```

Ядро не знает про WPF, поэтому его можно переиспользовать в консольной сборке,
веб-сервисе или CI-скрипте. `DitaStudio.Docx` тоже не зависит от WPF — только от ядра
и `DocumentFormat.OpenXml`.

## Ограничения текущей версии

- В режиме «Автор» содержимое плашек (например, alt-текст картинки, атрибуты ссылки)
  правится только в режиме исходного кода, не прямо в плашке.
- PDF: печатается через WebView2 или через установленный Edge/Chrome в фоновом режиме;
  своего движка вёрстки нет, свой текст колонтитулов работает только через WebView2.
  Без WebView2 Evergreen Runtime предпросмотр и печать через WebView2 недоступны.
- Внешний DTD вливается в общий каталог всего сеанса редактора: два открытых по очереди
  проекта с конфликтующими специализациями перезапишут элементы друг друга (побеждает
  последний загруженный).
- Из `.ditaval` читаются правила `exclude` и `flag`; `include` и `passthrough` пропускаются.
- XLIFF — по одному документу (без пакетного экспорта всей карты), пара языков фиксирована:
  `ru` → `en`.
- Git/SVN — только просмотр различий, коммитов и отправки изменений из редактора нет.
- Предметный указатель строится только в едином HTML-файле (и в PDF, который из него
  печатается); в многостраничном сайте и в DOCX `indexterm` не выводится.
- В DOCX не встраиваются SVG-изображения (Word/OpenXML не умеет их напрямую) — вместо
  картинки подставляется текстовая плашка с именем файла; растровые форматы
  (PNG/JPEG/GIF/BMP/TIFF) экспортируются полностью.
- Проверяется только орфография, грамматика — нет.
- Однопользовательский настольный редактор: совместного редактирования и серверной части нет.
