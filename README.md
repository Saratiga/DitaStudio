# DITA Studio

Настольный редактор технической документации на DITA 1.3 — аналог Oxygen XML Author,
написанный на C# (WPF, .NET 8) **без единой сторонней зависимости**: решение собирается
и запускается офлайн одной командой.

## Что умеет

**Режим «Автор»** — визуальное редактирование, как в текстовом процессоре, но каждая
правка сразу попадает в дерево DITA:

- текст правится прямо в оформленном виде; фразовые элементы (`b`, `codeph`, `uicontrol`,
  `filepath`, `term`…) показываются оформлением, а не тегами;
- `Enter` создаёт следующий абзац, пункт списка или шаг задачи; `Backspace` в начале блока
  объединяет его с предыдущим; `Tab` / `Shift+Tab` меняют уровень вложенности пункта;
- `Ctrl+B`, `Ctrl+I`, `Ctrl+U`, `Ctrl+\``, `Ctrl+Shift+U` оборачивают выделение в `b`, `i`,
  `u`, `codeph`, `uicontrol`;
- ссылки, изображения, сноски и элементы с `conref` показываются компактными плашками;
- таблицы CALS, `simpletable`, `properties` и `choicetable` редактируются по ячейкам;
- слева от блоков видны имена элементов (можно выключить в меню «Структура»).

**Режим «Исходный код»** — подсветка синтаксиса, автодополнение элементов и атрибутов
по каталогу DITA (`Ctrl+Пробел`), переход к строке из панели проверки. Переключение между
режимами синхронизирует модель в обе стороны.

**Режим «Предпросмотр»** — готовая HTML-страница топика с разрешёнными `conref` и `keyref`,
плюс кнопка «Открыть в браузере».

**Карты публикации** — дерево `ditamap` / `bookmap` с раскрытием вложенных карт, добавлением
топиков и разделов, перемещением и изменением уровня вложенности, подсветкой битых ссылок.

**Проверка** — по контент-моделям DITA, а не «на глазок»:

- допустимость и порядок дочерних элементов (сообщение подсказывает, что здесь уместно);
- обязательные атрибуты и значения перечислений;
- уникальность `@id`, битые `href` / `conref` / `conkeyref`, необъявленные ключи;
- редакторские замечания: пустой заголовок, отсутствующий `shortdesc`, картинка без `alt`.

**Публикация** — HTML-сайт с оглавлением и постраничной навигацией, единый HTML-файл,
экспорт в PDF (печать через установленный Edge или Chrome в фоновом режиме), условная
сборка по `props` / `platform` / `product` / `audience` / `otherprops`.

## Охват DITA 1.3

Каталог элементов задаётся текстовым описанием в `src/DitaStudio.Core/Schema/CatalogSource*.cs`
в синтаксисе, близком к DTD (параметрические сущности, контент-модели, списки атрибутов):

- базовый модуль `topic` со всеми блочными и фразовыми элементами;
- специализации `concept`, `task` (строгая и общая), `reference`, `troubleshooting`,
  `glossentry`, `glossgroup`;
- таблицы CALS, `simpletable`, `properties`, `choicetable`;
- пролог и метаданные;
- домены `hi-d`, `pr-d`, `sw-d`, `ui-d`, `ut-d`, `markup-d`/`xml-d`, `hazard-d`,
  `equation-d`, `svg-d`, `mathml-d`, `abbrev-d`, `indexing-d`, `release-management`;
- карты: `map`, `bookmap`, `subjectScheme`, `mapgroup-d`, `ditavalref-d`;
- модуль обучения: `learningBase`, `learningOverview`, `learningContent`, `learningSummary`,
  `learningAssessment`, `learningPlan` и интерактивные задания.

Каталог легко расширять: добавьте строку вида

```
имя :: @class :: отображение :: контент-модель :: атрибуты :: описание
```

и элемент сразу появится в палитре вставки, автодополнении, валидаторе и генераторе HTML.
Специализации собственной DTD подключаются тем же способом.

## Сборка и запуск

Нужен **.NET SDK 8.0** (проверить: `dotnet --version`).

```powershell
cd C:\Users\vova1\source\DitaStudio
dotnet build DitaStudio.sln -c Release
dotnet run --project src\DitaStudio.App
```

Проверки ядра:

```powershell
dotnet run --project tests\DitaStudio.Tests
```

Готовый исполняемый файл после сборки: `src\DitaStudio.App\bin\Release\net8.0-windows\DitaStudio.exe`.

Самодостаточный файл без установленного .NET:

```powershell
dotnet publish src\DitaStudio.App -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=true -o publish
```

## С чего начать

1. **Файл → Открыть папку проекта** и выберите `samples\GuideSample` — учебный проект
   с концепцией, двумя задачами, справкой, топиком об устранении неполадки и глоссарием.
2. Вкладка **Карта** слева — дерево публикации; двойной щелчок открывает топик.
3. **F7** — проверить проект, **F5** — собрать HTML-сайт.
4. Панель **Вставка** справа показывает только те элементы, которые допустимы
   в текущей позиции; двойной щелчок вставляет элемент.
5. **F1** — справка по элементу под курсором: контент-модель, атрибуты, модуль.

## Горячие клавиши

| Действие | Клавиши |
|---|---|
| Открыть папку проекта | `Ctrl+Shift+O` |
| Создать документ | `Ctrl+N` |
| Сохранить / сохранить всё | `Ctrl+S` / `Ctrl+Shift+S` |
| Закрыть вкладку | `Ctrl+W` |
| Панель вставки | `Ctrl+E` |
| Поиск по проекту | `Ctrl+Shift+F` |
| Проверить проект | `F7` |
| Собрать публикацию | `F5` |
| Справка по элементу | `F1` |
| Отменить структурное изменение | `Ctrl+Alt+Z` |
| Переместить элемент | `Ctrl+Shift+↑` / `Ctrl+Shift+↓` |

Обычные `Ctrl+Z` / `Ctrl+Y` внутри текстового блока отменяют набор текста; `Ctrl+Alt+Z`
откатывает структурные операции (вставку, удаление, перемещение, правку исходного кода).

## Устройство решения

```
src/DitaStudio.Core/          ядро, не зависит от интерфейса
  Model/                      DOM: узлы, документ, сериализация
  Schema/                     каталог DITA 1.3, разбор контент-моделей, автомат допустимости
  Validation/                 проверка структуры, атрибутов, стиля
  Project/                    папка проекта, ditamap, ключи, conref/keyref, поиск
  Publishing/                 генератор HTML, подписи, стили, печать в PDF
  Editing/                    структурные операции и история отмены
  Templates/                  заготовки новых документов
src/DitaStudio.App/           интерфейс WPF
  Authoring/                  режим «Автор», редактор строки, редактор исходного кода
  Views/                      вкладка документа, диалоги
tests/DitaStudio.Tests/       проверки ядра (обычная консольная программа, без xunit)
samples/GuideSample/          учебный проект DITA
```

Ядро не знает про WPF, поэтому его можно переиспользовать в консольной сборке,
веб-сервисе или CI-скрипте.

## Ограничения текущей версии

- Внешние DTD не загружаются: структура проверяется по встроенному каталогу.
  Для нестандартных специализаций добавьте их описание в `CatalogSource`.
- В режиме «Автор» глубоко вложенные фразовые элементы (`b` внутри `ph` внутри `xref`)
  редактируются как плашки — тонкую правку удобнее делать в режиме исходного кода.
- PDF собирается печатью HTML через Edge или Chrome; при их отсутствии откройте
  собранный HTML и напечатайте вручную.
- `ditaval`-файлы пока не читаются; условия сборки задаются в диалоге
  **Публикация → Условия сборки**.
