# DITA Studio

Настольный редактор технической документации на DITA 1.3 — аналог Oxygen XML Author,
написанный на C# (.NET 8). Основная версия — кроссплатформенная, на **Avalonia UI**
(Windows, Linux, macOS; `src/DitaStudio.Desktop`); прежняя WPF-версия для Windows
(`src/DitaStudio.App`) сохраняется как легаси. Обе оболочки используют одно ядро
(`DitaStudio.Core`, без внешних зависимостей) и общие модели представления
(`DitaStudio.Presentation`); экспорт в Word — `DitaStudio.Docx` → DocumentFormat.OpenXml.

Готовые сборки (не требуют установленного .NET) — на странице
[релизов](https://github.com/Saratiga/DitaStudio/releases): Windows x64, Linux x64,
macOS (Intel, на Apple Silicon — через Rosetta) и легаси-сборка WPF. Предпросмотр и печать
в PDF — встроенный Chromium, отдельно ничего ставить не нужно.

## Что умеет

**Режим «Автор»** — визуальное редактирование, как в текстовом процессоре, но каждая
правка сразу попадает в дерево DITA и проверяется по контент-модели — получить
невалидный документ через этот режим нельзя:

- текст правится прямо в оформленном виде; фразовые элементы (`b`, `codeph`, `uicontrol`,
  `filepath`, `term`…) показываются оформлением, а не тегами;
- `Enter` создаёт следующий абзац, пункт списка или шаг задачи; `Backspace` в начале блока
  объединяет его с предыдущим; `Tab` / `Shift+Tab` меняют уровень вложенности пункта;
- `Ctrl+B`, `Ctrl+I`, `Ctrl+U`, `Ctrl+\``, `Ctrl+Shift+U` оборачивают выделение в `b`, `i`,
  `u`, `codeph`, `uicontrol`;
- ссылки, изображения и элементы с `conref` показываются компактными плашками;
  сноска (`fn`) вставляется через «Вставка → Сноска» на месте курсора (выделенный текст
  становится текстом сноски): в тексте — плашка «сноска N», а сам текст сноски правится в
  области «Сноски» внизу топика; печатается на той же странице сайта, где стоит ссылка на
  неё, а в DOCX — как настоящая сноска Word;
- топик может быть без заголовка (пустой `<title/>`, заготовка «Таблица (без заголовка)») —
  заголовок не печатается и в оглавление не попадает;
- фразовые элементы из панели «Вставка» (термин, сноска, изображение…) встают на место
  курсора, а не отдельным блоком после абзаца;
- таблицы CALS, `simpletable`, `properties` и `choicetable` редактируются по ячейкам,
  включая объединение по горизонтали и вертикали (`Ctrl+Alt+→` / `Ctrl+Alt+↓`), разделение
  ячеек, вставку и удаление строк и столбцов из меню ячейки по правой кнопке мыши, ширину
  столбцов и высоту строк — перетаскиванием границ мышью (доли `colwidth`/`relcolwidth`,
  высота — классом `row-height-Nmm`; HTML/PDF/DOCX их учитывают);
- работает проверка орфографии по словарям Hunspell (русский и английский): ошибки
  подчёркиваются волной, варианты исправления и «Пропустить все» — в контекстном меню;
- блоки-обёртки (`div`, `section`, `sectiondiv`, `fig`…) обведены полосой с подписью,
  сноски вынесены вниз, в область «Сноски»;
- оформление без CSS и XML: выравнивание блока (по левому краю, центру, правому краю,
  ширине), размер шрифта (8–28 пт) и цвет текста выделения или дальнейшего набора (как в
  Word), нумерованные абзацы с номером по заголовкам (2.3.1, как пункты по ГОСТ 2.105),
  положение блока на отдельном листе PDF/DOCX (девять областей: вверху/посередине/внизу ×
  слева/по центру/справа) — на панели и в меню «Оформление»; пишется классом `outputclass` (у ячеек — `align`),
  публикация HTML/PDF/DOCX его понимает;
- `Enter` в конце блока показывает подсказку, какой элемент вставить дальше (с описанием,
  фильтром; первая строка — обычный Enter), отключается в меню «Структура»;
- изображения видны картинками (в строке и блоком), размер меняется мышью за маркер в углу
  (пишется `width` в px);
- в том же контекстном меню — «Вставить элемент»: частые вставки и все элементы, допустимые
  у курсора (в строку текста или блоком после текущего);
  код, пути и имена команд не проверяются;
- слева от блоков видны имена элементов (можно выключить в меню «Структура»).

**Режим «Исходный код»** — подсветка синтаксиса, автодополнение элементов и атрибутов
по каталогу DITA (`Ctrl+Пробел`), переход к строке из панели проверки. Переключение между
режимами синхронизирует модель в обе стороны.

**Режим «Предпросмотр»** — топик с разрешёнными `conref` и `keyref` в одном из трёх видов:
HTML, PDF (настоящая печать с реальной разбивкой на страницы) или DOCX (приближённо —
HTML со стилем, подобранным под экспорт в Word). Кнопка «Открыть внешним приложением»
показывает тот же результат в браузере или программе просмотра PDF.

**Карты публикации** — дерево `ditamap` / `bookmap` с раскрытием вложенных карт, добавлением
топиков и разделов; порядок и вложенность меняются кнопками или перетаскиванием; контекстное
меню строки (свойства, добавить до / после / внутрь, дублировать, найти ссылки, вырезать /
копировать / вставить, переименовать или удалить файл); флажок «публиковать» у строки —
снятый исключает топик с веткой из всех форматов (`processing-role="resource-only"`);
подсветка битых ссылок; редактор таблицы соответствий (`reltable` → «Смотрите также»); области
ключей (`keyscope`) — разные значения одного ключа в разных ветках карты.

**Проверка** — по контент-моделям DITA, а не «на глазок»:

- допустимость и порядок дочерних элементов (сообщение подсказывает, что здесь уместно);
- обязательные атрибуты и значения перечислений;
- уникальность `@id`, битые `href` / `conref` / `conkeyref`, необъявленные ключи;
- редакторские замечания: пустой заголовок, отсутствующий `shortdesc`, картинка без `alt`;
- дополнительные правила из плагинов.

**Поиск по проекту** — обычный текст или регулярное выражение (.NET), поиск по именам
элементов, замена всех вхождений сразу по всему проекту.

**Рефакторинг** — переименование `id` и перенос/переименование файла с обновлением всех
`href`/`conref` в проекте; вынесение элемента в `conref` (в существующий топик или новый файл).

**Рецензирование** — пометка изменений атрибутом `rev` (полоса на полях при публикации),
track changes через штатный `status="new"/"deleted"` с автором и датой (принять/отклонить),
сравнение двух файлов с построчным переносом различий, сравнение открытого документа с
последним коммитом git или с версией BASE в SVN.

**Публикация** — HTML-сайт с оглавлением и постраничной навигацией, единый HTML-файл
с алфавитным предметным указателем (`indexterm`), **экспорт в DOCX** (нативная сборка в
OOXML, а не конвертация HTML: настоящие сноски Word, поле оглавления (сразу со строками-ссылками,
номера страниц Word проставит при открытии), объединение ячеек
таблиц, разрывы страниц), экспорт в PDF (печать встроенным Chromium со своими колонтитулами
и номерами страниц; запасной путь — установленный Edge/Chrome), подключаемый
пользовательский CSS.

**Оформление DOCX** — тот же пользовательский CSS, что и для сайта, превращается в именованные
стили Word: шрифты, цвета, отступы, рамки, таблицы, размер и поля страницы (`@page`), правила
только для Word — в `@media docx`, собственные классы `outputclass` — в производные стили.
То, чего CSS не умеет, задаётся диалогом «Публикация → Оформление DOCX…»: титульная страница,
оглавление нужной глубины, нумерация заголовков 1 / 1.1 / 1.1.1, колонтитулы с номерами
страниц и картинкой (логотипом) слева, по центру или справа — она же в колонтитулах PDF,
переплёт и зеркальные поля, язык и переносы. Размер бумаги, ориентация и поля —
диалог «Публикация → Параметры страницы…» со схемой листа (для DOCX и PDF, главнее `@page`).
Заголовок можно пометить «без номера» (правая кнопка на заголовке) — он не нумеруется и не
попадает в оглавление; название оглавления («Содержание», «Оглавление», своё) задаётся там же,
где его глубина.

**Условная сборка** — исключение содержимого по `props` / `platform` / `product` /
`audience` / `otherprops` / `deliveryTarget`: через диалог или через связанный с проектом
файл `.ditaval` (правила `exclude` и `flag` — подсветка цветом, фоном, начертанием, полосой
изменений). Файл перечитывается при каждой сборке и редактируется прямо из приложения.

**Перевод** — экспорт открытого топика в XLIFF 1.2 (фразовая разметка — как `bpt`/`ept`/`ph`)
и импорт готового перевода обратно в документ.

**Проект** — восемь последних открытых папок в «Файл → Недавние проекты»; подключение
других проектов как источников ключей (`keyref`/`conref` ищутся и там); подключение
внешнего DTD с собственными специализациями; пересборка пространства ключей при сохранении.

**Сохранность правок** — файлы записываются атомарно (сначала во временный файл рядом,
потом подмена оригинала), поэтому сбой посреди сохранения не оставит обрезанный документ.
Каждые 30 секунд несохранённые правки копируются в `%LOCALAPPDATA%\DitaStudio\Recovery`;
после аварийного завершения редактор предложит восстановить их при следующем открытии
проекта. Если открытый файл поменяла другая программа (git pull, другой редактор),
вкладка без правок перечитывается сама, а вкладка с правками спрашивает, чью версию
оставить. Смена проекта, как и выход, сначала предлагает сохранить изменения.

**Расширяемость** — плагины (.dll в папке `plugins` рядом с exe): свои правила проверки,
свои форматы публикации, свои команды режима «Автор».

**Оформление** — светлая и тёмная тема («Справка → Тёмная тема», выбор запоминается).

## Охват DITA 1.3

Каталог элементов задаётся текстовым описанием в `src/DitaStudio.Core/Schema/CatalogSource*.cs`
в синтаксисе, близком к DTD (параметрические сущности, контент-модели, списки атрибутов):

- базовый модуль `topic` со всеми блочными и фразовыми элементами;
- специализации `concept`, `task` (строгая и общая), `reference`, `troubleshooting`,
  `glossentry`, `glossgroup`;
- таблицы CALS, `simpletable`, `properties`, `choicetable`;
- пролог и метаданные;
- домены `hi-d`, `pr-d`, `sw-d`, `ui-d`, `ut-d`, `markup-d`/`xml-d`, `hazard-d`,
  `equation-d`, `svg-d`, `mathml-d`, `abbrev-d`, `indexing-d`, `release-management`;
- карты: `map`, `bookmap`, `subjectScheme`, `mapgroup-d`, `ditavalref-d`;
- модуль обучения: `learningBase`, `learningOverview`, `learningContent`, `learningSummary`,
  `learningAssessment`, `learningPlan` и интерактивные задания.

Каталог легко расширять: добавьте строку вида

```
имя :: @class :: отображение :: контент-модель :: атрибуты :: описание
```

и элемент сразу появится в палитре вставки, автодополнении, валидаторе и генераторах
HTML/DOCX. Собственные специализации можно не описывать вручную, а подключить готовым
DTD: «Файл → Подключить внешний DTD…» разбирает настоящий DTD-синтаксис (`ENTITY`,
`ELEMENT`, `ATTLIST`, параметрические сущности, подключаемые модули) и вливает элементы
в тот же каталог.

## Сборка и запуск

Нужен **.NET SDK 8.0** (проверить: `dotnet --version`).

Кроссплатформенная версия (Windows, Linux, macOS):

```bash
dotnet run --project src/DitaStudio.Desktop
```

Самодостаточная сборка без установленного .NET (так собираются архивы для релиза; собирать
нужно на той ОС, для которой сборка, — нативный Chromium копируется только так):

```bash
dotnet publish src/DitaStudio.Desktop -c Release -r linux-x64 --self-contained true -o publish   # или win-x64, osx-x64
```

Сборка весит около 450 МБ (из них ~350 МБ — встроенный Chromium); пакеты NuGet при первой
сборке занимают ~1,5 ГБ — в них Chromium сразу для трёх ОС.

Легаси-версия WPF (только Windows):

```powershell
dotnet build DitaStudio.sln -c Release
dotnet run --project src\DitaStudio.App
dotnet publish src\DitaStudio.App -c Release -r win-x64 --self-contained true -o publish
```

## Тесты

```powershell
dotnet test tests\DitaStudio.Tests          # ~860 проверок ядра и DOCX-экспорта
dotnet test tests\DitaStudio.Desktop.Tests  # интерфейс Avalonia (headless, в т.ч. на Linux)
dotnet test tests\DitaStudio.UiTests          # UI-тесты легаси-версии WPF на реальном DitaStudio.exe
```

Тесты интерфейса Avalonia идут без экрана (Avalonia.Headless) и сохраняют снимки окон в
`tests/DitaStudio.Desktop.Tests/bin/Debug/net8.0/screenshots`; среди них — проверки паритета
с WPF (все пункты меню и подсказки кнопок, сценарии UI-тестов WPF). Встроенный Chromium
проверяется отдельно, под X-сервером:
`DITASTUDIO_CEF_TESTS=1 xvfb-run -a dotnet test tests/DitaStudio.Desktop.Tests --filter FullyQualifiedName~CefPreviewTests`.

Проверки ядра — проект xUnit: каждый раздел проверок (каталог, валидация, DOCX и т. д.) —
отдельный тест, и упавший тест перечисляет все непрошедшие проверки раздела, а не только
первую. Помимо примеров там есть property-based проверки (контент-модели, DTD, XLIFF,
`.ditaval`) со случайными входными данными на фиксированном зерне.

На каждый пуш GitHub Actions (`.github/workflows/ci.yml`) на Windows собирает всё решение и
прогоняет проверки ядра с покрытием кода (сводка — на странице прогона, полный HTML-отчёт —
в артефакте `test-results`), а на Linux — тесты интерфейса Avalonia и встроенного Chromium
(снимки окон — в артефакте `desktop-screenshots`). Локально покрытие считается так:

```powershell
dotnet test tests\DitaStudio.Tests --settings tests\DitaStudio.Tests\coverage.runsettings
```

UI-тесты гоняет отдельный workflow `ui-tests.yml` — после пуша в `master` и вручную
(Actions → UI tests → Run workflow); при падении к прогону прикладывается снимок экрана.

Релиз: пуш тега `vX.Y.Z` (равного `<Version>` в `DitaStudio.Desktop.csproj` и
`DitaStudio.App.csproj`) запускает `release.yml` — тесты, самодостаточные сборки на раннерах
каждой ОС и черновик релиза с архивами `DitaStudio-vX.Y.Z-win-x64.zip`,
`-linux-x64.tar.gz`, `-osx-x64.tar.gz` и `DitaStudio-Legacy-WPF-vX.Y.Z-win-x64.zip`; текст
«Что нового» дописывается вручную перед публикацией. Ручной запуск — пробная сборка без релиза.

UI-тесты WPF (xUnit + FlaUI) запускают собранный `DitaStudio.exe` и управляют им через UI
Automation, поэтому решение нужно собрать заранее. Та же библиотека управления доступна
из командной строки для ручной проверки: `dotnet run --project tools\UiHarness -- --help`.

Полный чек-лист функционального тестирования — [docs/TESTPLAN.md](docs/TESTPLAN.md).

## С чего начать

1. **Файл → Открыть папку проекта** и выберите `samples\DitaStudioGuide` — руководство
   пользователя по самому DITA Studio, оформленное как DITA-проект (заодно демонстрирует
   сноски, разрывы страниц и объединение ячеек). Для более простого учебного примера —
   `samples\GuideSample`. Свой проект с нуля — по шагам в разделе
   [«Создание проекта с нуля»](USAGE.md#создание-проекта-с-нуля) руководства.
2. Вкладка **Карта** слева — дерево публикации; двойной щелчок открывает топик,
   перетаскивание меняет порядок.
3. **F7** — проверить проект, **F5** — собрать HTML-сайт.
4. Панель **Вставка** справа показывает только те элементы, которые допустимы
   в текущей позиции; двойной щелчок вставляет элемент.
5. **F1** — справка по элементу под курсором: контент-модель, атрибуты, модуль.

Подробный разбор всех возможностей — в [USAGE.md](USAGE.md).

операции (вставку, удаление, перемещение, правку исходного кода).

## Устройство решения

```
src/DitaStudio.Core/            ядро, не зависит от интерфейса
  Model/                        DOM: узлы, документ, сериализация
  IO/                           атомарная запись, отпечаток файла, копии для восстановления
  Schema/                       каталог DITA 1.3, разбор контент-моделей, автомат допустимости
  Schema/Dtd/                   чтение внешних DTD (кастомные специализации)
  Validation/                   проверка структуры, атрибутов, стиля
  Project/                      папка проекта, ditamap, ключи, conref/keyref, поиск/замена,
                                .ditaval, рефакторинг
  Publishing/                   генератор HTML, подписи, стили, печать в PDF
  Editing/                      структурные операции, история отмены, track changes
  Diff/                         построчное сравнение, чтение версий из git/SVN
  Localization/                 экспорт/импорт XLIFF 1.2
  Plugins/                      загрузчик плагинов
```

## Ограничения текущей версии

- В режиме «Автор» содержимое плашек (например, alt-текст картинки, атрибуты ссылки)
  правится только в режиме исходного кода, не прямо в плашке.
- PDF печатается встроенным Chromium (в легаси-версии — WebView2); своего движка вёрстки нет.
  Если Chromium не запустился, предпросмотр открывается внешним браузером, а PDF печатается
  установленным Edge/Chrome — уже без своих колонтитулов.
- Сборка для macOS — только под Intel (встроенный Chromium CefGlue выпускается под x64), на
  Apple Silicon работает через Rosetta; приложение не подписано. Сочетания клавиш на macOS —
  с `Ctrl`, как на Windows и Linux, а не с `Cmd`.
- Первое открытие большого топика (сотни абзацев) в режиме «Автор» занимает около секунды:
  каждый блок — отдельный редактор. Правки после этого перестраивают только затронутые блоки.
- Из `.ditaval` читаются правила `exclude` и `flag`; `include` и `passthrough` пропускаются.
- Предпросмотр «DOCX (приближённо)» показывает HTML со стилем, похожим на Word: настройки
  «Оформление DOCX» (титул, нумерация заголовков, колонтитулы) и правила `@media docx` в нём
  не видны — только в самом экспортированном файле.
- Из CSS в DOCX переносится оформление текста, абзацев, рамок и таблиц; вёрстка веб-страницы
  (flex, позиционирование), тени, скругления, фоновые картинки, картинки-маркеры и вид нумерации
  `ol` (буквы, римские цифры) в Word не переносятся.
- Условия сборки применяются к содержимому топиков, но не к ссылкам карты: `topicref` с
  исключённым `product`/`audience`/… всё равно попадает в публикацию.
- Схема категорий (`subjectScheme`) создаётся и проверяется как карта, но значения условных
  атрибутов в топиках по ней не проверяются.
- XLIFF — по одному документу (без пакетного экспорта всей карты), пара языков фиксирована:
  `ru` → `en`.
- Git/SVN — только просмотр различий, коммитов и отправки изменений из редактора нет.
- Предметный указатель строится только в едином HTML-файле (и в PDF, который из него
  печатается); в многостраничном сайте и в DOCX `indexterm` не выводится.
- В DOCX не встраиваются SVG-изображения (Word/OpenXML не умеет их напрямую) — вместо
  картинки подставляется текстовая плашка с именем файла; растровые форматы
  (PNG/JPEG/GIF/BMP/TIFF) экспортируются полностью.
- Проверяется только орфография (русский и английский), грамматика — нет.
- Однопользовательский настольный редактор: совместного редактирования и серверной части нет.
