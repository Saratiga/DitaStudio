# Локализация интерфейса: план

Решения пользователя: языки — **русский и английский**; **основной — английский**. Язык выбирается так: **сохранённый выбор
пользователя → язык системы (если поддерживается) → английский**. Выбор пользователя запоминается между запусками.

## Как устроено

- Строки — ресурсы `.resx` в `src/DitaStudio.Core/Resources`: `Strings.resx` (английский, основной, он же откат) и
  `Strings.ru.resx`. Один общий набор для всех сборок: Core, Docx, Presentation и Desktop берут строки через `Loc`.
- Ключи — `Область_Смысл` без точек (`Menu_File`, `Msg_SaveFailed`, `Dlg_Table_Title`): точки в привязках XAML мешают.
- Доступ: `Loc.T("Ключ")` / `Loc.T("Ключ", арг…)` в коде (подстановка `{0}` в ресурсе); `{loc:Tr Ключ}` в XAML — привязка, которая
  обновляется при смене языка без перезапуска. Нет ключа в языке — берётся английский, нет и там — виден сам ключ.
- Выбор языка: `UiLanguages.Resolve` (сохранённое → язык системы по порядку: UI-язык, региональные настройки, язык установки
  Windows → английский), `LanguageSettings` — файл `%APPDATA%\DitaStudio\language.txt`, нет файла — «как в системе».
  Меню **Справка → Язык**: «Как в системе», English, Русский (названия — на самих языках).
- Тесты: `LocalizationTests` (ядро) — правила выбора, запоминание, сброс, **полнота ресурсов** (набор ключей en = ru, нет пустых,
  одинаковые подстановки `{0}`) и **каждый ключ из кода и XAML есть в ресурсах**. Тесты закрепляют русский язык
  (`TestLanguage`) и свой файл настройки — не зависят от языка машины и выбора пользователя.
- Язык **публикации** (подписи «Содержание», «Примечание» в HTML/DOCX) — отдельная вещь: `Labels.For(options.Language)` по языку
  документа, не по языку интерфейса.

## Этапы

| № | Этап | Статус |
|---|---|---|
| 1 | Инфраструктура: ресурсы, `Loc`, выбор и запоминание языка, меню «Язык», `{loc:Tr}`, тесты полноты | ☑ |
| 2 | XAML: меню, подсказки, подписи панелей и вкладок (`MainWindow.axaml`) — 238 строк | ☑ |
| 3 | Desktop (C#): диалоги `AvaloniaDialogService.*`, меню «Автора», окна, подписи в коде — 431 литерал | ☑ |
| 4 | Presentation: сообщения и подписи ViewModel'ей (строка состояния, вопросы, ошибки) — 419 литералов | ☑ |
| 5 | Core и Docx: сообщения проверки, ошибки, журнал сборки, названия цветов и положений, шаблоны в диалоге «Создать документ» — 182 литерала. Таблицы, построенные один раз, стали свойствами (меняются с языком) | ☑ |
| 6 | Каталог элементов DITA: описания 421 элемента и атрибутов (`Elem_имя`, `Attr_имя`; `ElementDef.Description` и `AttributeDef.Description` берут строку на языке интерфейса, нет перевода — текст каталога) | ☑ |

Остаётся по-русски (сознательно, это содержимое, а не интерфейс): подписи публикации (`Labels`), названия стилей Word
(`DocxStyleCatalog`), HTML-вставки публикации («В карте нет топиков…»), текст оглавления Word, суффикс «-копия» в id.
Тексты уже открытых вкладок и диалогов, собранные в коде один раз, обновляются при повторном открытии.

Строки с подстановкой (`$"…{x}…"`) переводятся в `Loc.T("Ключ", x)`; порядок слов в английском может отличаться — подстановки
нумеруются в ресурсе.
