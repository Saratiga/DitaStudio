## 1. Лишние линии в таблицах DOCX

- **Причина (воспроизведено).** Правило для ячеек через селектор (`.blue-frame td { border: … }`, `table.x td`, `tr:nth-child(2n) td`) превращается
  не только в рамки ячейки (`tcBorders`), но и в производный стиль абзаца внутри ячейки (`TableText__blue_frame_td`) с теми же рамками —
  `w:pBdr`. Отсюда вторые линии над и под текстом каждой ячейки и «разорванные» вертикали на снимке. Так же ведут себя `padding`
  (уходит в отступы абзаца), `background-color` и `margin`.
- **Делаем.** Для элементов таблицы (`entry`, `stentry`, `row`, `thead`, `tbody`, `tgroup`, `table`, `simpletable`…) свойства «коробки» — `border*`, `background*`,
  `padding*`, `margin*`, `width`, `height` — идут только в свойства ячейки/таблицы (`tcBorders`, `shd`, `tcMar`, `tblBorders`), в стиль абзаца — только
  текст (шрифт, цвет, начертание, выравнивание). `padding` ячейки → поля ячейки (`tcMar`), сейчас он не переносится вовсе.
  Цвет рамок ячеек и таблицы из CSS — как задан; общая рамка таблицы и рамки ячеек не дублируются.
- **Проверка.** Документ из замечания (таблица с классом, `td`/`th` с рамками, `padding`): ни одного `w:pBdr` в абзацах ячеек, `tcBorders` и `tcMar` с нужными
  значениями, `OpenXmlValidator`; снимок отрисовки — вручную в Word (TESTPLAN).

## 2. Стили таблиц из шаблона DOCX

- **Сейчас.** Стили таблиц шаблона (`w:style w:type="table"`, например «Сетка таблицы» или фирменный с чередованием строк) копируются в документ вместе с
  остальными, но таблицы на них не ссылаются (`tblStyle` нет) и рисуются своими рамками.
- **Делаем.** Таблица получает стиль из шаблона:
  1. по классу: `outputclass="Фирменная"` у таблицы → стиль таблицы шаблона с таким id или названием (без учёта регистра, пробелов и дефисов);
  2. иначе — стиль таблиц по умолчанию, выбранный в «Оформление DOCX» (новый список «Стиль таблиц» — стили таблиц из шаблона, «нет» — как сейчас).
  Если стиль таблицы назначен, наши рамки и заливка по умолчанию не пишутся (их даёт стиль), шапка (`thead`) отмечается как «строка заголовка»
  (`tblLook firstRow`), чтобы работало условное оформление стиля; явные правила CSS для этой таблицы и её ячеек по-прежнему главнее.

## 3. Контекстное меню не закрывается

- **Что видно.** Меню «Автора» открываются вручную (`ContextMenu.Open(this)`: меню текста блока, меню ячеек, меню выделенных блоков) — не через
  обычный механизм контекстного меню. Предположение (проверю тестом): при ПКМ по таблице открывается второе меню поверх первого, а щелчок мимо не
  закрывает меню, открытое таким способом.
- **Делаем.** Одно открытое меню на «Автор»: перед открытием нового закрывается прежнее; щелчок любой кнопкой мыши вне меню, прокрутка, `Esc`,
  потеря фокуса окном закрывают его. Сначала — тест, воспроизводящий случай «ПКМ по тексту, затем ПКМ по таблице» и «ПКМ, затем щелчок мимо».
- **Проверка.** Headless: после щелчка мимо и после ПКМ в другом месте открыто не больше одного меню.

## 7. Кнопки оформления отражают текст под курсором

- **Делаем.** Кнопки Ж, К, Ч, `</>` (и другие кнопки фразового оформления на панели и в меню) подсвечиваются («нажаты»), когда курсор или выделение в тексте
  с таким оформлением. Нажатие подсвеченной кнопки снимает оформление: с выделения — только с выделенной части (элемент разрезается), без выделения —
  со всего элемента под курсором. То же для размера и цвета текста, маркера и выравнивания: поле размера показывает текущий размер, кнопки цвета/маркера —
  текущий цвет, кнопка выравнивания — текущее. Ctrl+B/I/U работают так же (переключают).
- **Проверка.** Ядро/представление: снятие оформления с части текста и с элемента целиком, вложенное оформление (`b` в `i`). Headless: состояние кнопок
  при перемещении курсора, снятие оформления кнопкой, одна отмена.

## 8. Размер изображения мышью в любом блоке

- **Что видно.** Маркер размера есть у картинок в тексте и у рисунка (`fig`). В ячейке таблицы картинка тоже строится с маркером; вероятная причина —
  протаскивание перехватывает выделение ячеек мышью (проверю тестом). Картинки в других местах (пункт списка с вложенным блоком, примечание, `fig` в ячейке) — проверить по одному.
- **Делаем.** Нажатие на маркер не начинает выделение ячеек/блоков; маркер у картинки в любом блоке («Автор» строит картинку одним способом). Ширина
  ограничивается шириной ячейки/блока.
- **Проверка.** Headless: перетаскивание маркера у картинки в ячейке, в примечании, в пункте списка — `width` записан, выделение ячеек не началось.
