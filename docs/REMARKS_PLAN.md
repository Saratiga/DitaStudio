### 1. Полоса прокрутки вкладок карт
- **Причина.** `MainWindow.axaml:357` — `ListBox MapTabs` с `HorizontalScrollBarVisibility="Auto"`: стандартная полоса Fluent (≈ 16 px) рисуется поверх вкладок.
- **Делаем.** Тонкая полоса (≈ 4–6 px, при наведении шире) стилем в `Themes/Controls.axaml` для `MapTabs`, либо `AllowAutoHide`/полоса под вкладками с отступом снизу у элемента вкладки. Лучше стиль, чем отступ: не растёт высота панели.
- **Проверка.** Снимок окна (headless) в светлой и тёмной теме: название карты читается целиком при длинном списке вкладок; полоса не закрывает текст.

### 2. Ctrl+V в таблице
- **Что видно.** `AuthorView.Selection.cs:456` `PasteBlocksAsync` вставляет блоки из буфера по `BlockClipboard.FindInsertion` (после якоря, выше по цепочке). Внутри ячейки `entry` допустимого места для таких блоков может не оказаться, а текст из Word/Excel (табличный, с табуляциями) вообще не разбирается — «в буфере нет блоков DITA».
- **?** Что именно копируете и куда: (а) блоки DITA из самого «Автора» в ячейку; (б) строки/ячейки таблицы из «Автора» в другую таблицу; (в) таблицу из Word/Excel? От ответа зависит объём; в плане — все три по возрастанию сложности.
- **Делаем.** Сначала воспроизвести каждый случай тестом. (а) — `FindInsertion` для якоря в `entry`: вставка внутрь ячейки, а не после таблицы. (б) — вставка строк (`row`) перед/после выбранной строки, ячеек в строку. (в) — разбор TSV/HTML-таблицы из буфера в `table` (`TableNodeBuilder` уже есть).
- **Проверка.** Headless: по каждому случаю результат в модели и одна отмена; сообщение в строке состояния, если вставить нельзя, с причиной.

### 3. Нумерованный абзац: убрать стиранием «№»
- **Что видно.** «№» — `TextBlock` слева от редактора (`AuthorView.TitleBadges.cs:51`), в тексте блока его нет, поэтому стереть его нельзя; снять нумерацию можно только меню «Нумерованный абзац».
- **Делаем.** Backspace в самом начале блока (курсор 0, нет выделения) у нумерованного абзаца снимает класс `numbered` (как `ToggleCurrentOutputClass`) — одной структурной правкой с отменой; тот же эффект у `Delete`/щелчка по «№» при выделенной метке. Backspace в начале обычного абзаца ведёт себя как раньше (слияние).
- **Проверка.** Backspace в начале → класс снят, метка исчезла, текст цел, одна отмена возвращает; второй Backspace — слияние с предыдущим.

### 4. Серая метка не пропадает
- **Причина.** Метка строится один раз в `BuildNode` (`AuthorView.Building.cs:28`); правка атрибута из панели («Атрибуты») модель меняет, а представление не перестраивает.
- **Делаем.** После записи атрибута/класса из панели и меню оформления — обновлять метку: найти обёртку узла (`_views[node]`) и пересобрать только её через `RebuildAround`/замену `TextBlock` с `Tag = "attribute-note"`; если заметок не осталось — снять обёртку.
- **Проверка.** Убрать `product`, потом `outputclass` у блока: метка меняется/исчезает без перезагрузки документа; отмена возвращает метку.

### 5. Серая метка для других атрибутов
- **Что видно.** Метка уже показывает любые атрибуты, кроме служебных (`id`, `class`, `domains`…), раскладки таблицы и классов оформления с префиксами `align-`/`size-`/`color-`/`mark-`/`frame-`/`row-height-`/`place-`/`page-break-` (`AuthorView.AttributeNotes.cs`).
- **?** Какие атрибуты вы имеете в виду? Кандидаты: (а) атрибуты у фразовых элементов (внутри абзаца метки нет, только у блоков); (б) атрибуты ячеек/строк таблицы; (в) `href`/`keyref`/`conref`/`scope`; (г) классы оформления с префиксами из списка выше; (д) атрибуты у `id`.
- **Делаем после ответа.** Расширить `AttributeNote`/места построения; для фразовых — не метку над блоком, а подсказку/подчёркивание.

### 6. Значок рисунка: «обычный» или «с нумерацией»

- **Делаем.** После выбора файла спросить (диалог из трёх кнопок: «С нумерацией», «Обычный рисунок», «Отмена»; запоминать выбор галочкой «больше не спрашивать» — **?** нужна ли). «Обычный» — вставить `image` (с `<alt>`) в позицию курсора и всё: без `fig`, без названия, `placement="inline"` по умолчанию. «С нумерацией» — как сейчас.

### 7. Размер колонтитула в CSS
- **Что видно.** `@page { @top-… }` поддерживается (`PageMarginBoxes`, `DocxHeaderFooter`): текст, `font-size`, высота картинки (`HeightMm`); высота самой области колонтитула и расстояние до края — не из CSS (`DocxLayout`/диалог).
- **?** «Размер» — это кегль текста (уже есть `font-size` в боксе), высота области колонтитула, отступ от края листа или размер картинки? В плане берём все три: `@top-center { height: 15mm }` (высота области), `@page { margin-top: …; @top-… { margin-top: … } }` → `w:pgMar header/footer`, `font-size` на уровне `@page` для всех боксов.
- **Проверка.** DOCX: значения в `w:pgMar`/`w:trHeight`; `CheckValidDocx`; в PDF — те же поля; журнал сборки предупреждает о неподдержанном свойстве.

### 8. Оглавление целиком из CSS
- **Что видно (картинка в замечании).** Автор пишет селекторы `.toc-title`, `.toc`, `.toc .lvl1/.lvl2`, `.toc .lvl1 > .num`, `text-transform: uppercase`, `display: inline-block`, `min-width`, `margin-right`. Сейчас:
  - DOCX: оглавление — поле Word `TOC` со стилями `TOC1…TOC6`; селекторы стилей — только `.doc-toc-N` и `.doc-toc-title` (`DocxStyleCatalog.cs:141,166`); название и глубина берутся из диалога (`DocxLayout.TocTitle`, `TocDepth`), не из CSS.
  - HTML-сайт: навигация `aside.toc` с `li`/`a` без классов уровня и номера (`HtmlPublisher.BuildToc`), хотя CSS-селекторы `.toc` в ней срабатывают.
  - Номер главы (`.num`) отдельным элементом нигде не выводится.
- **Делаем.**
  1. Единый словарь классов: `.toc-title`, `.toc`, `.toc .lvl1…lvl6`, у строки — `.num` (номер) и `.text` (заголовок). HTML-навигация и «содержание» единого файла/PDF размечаются так же (`<li class="lvl2"><span class="num">1.2</span> …`).
  2. DOCX: те же селекторы — синонимы стилей (`.toc-title` → TOCHeading, `.toc .lvlN` → TOC N, `.toc` → база строк оглавления); `text-transform: uppercase` → `w:caps`, `font-family/size/weight/margin`, `display:block`, отступы уровня.
  3. `.num` с `min-width`/`margin-right` в DOCX — как позиция табуляции в стиле TOC N (имитация «таба между цифрой и текстом»), номер и заголовок в строке поля разделяются табом.
  4. Название: `.toc-title::before { content: "Содержание" }` (или `content` на самом `.toc-title`) перекрывает название из диалога; без CSS — как сейчас.
  5. Уровни: `.toc .lvl4 { display: none }` убирает уровень из оглавления (→ `\o "1-3"`); `.toc { display: none }` убирает оглавление; новых полей в диалоге не нужно, диалог остаётся запасным способом.
  6. Предупреждения в журнале сборки на непонятые правила (как у других селекторов).
- **Проверка.** Тест на CSS из замечания: `OpenXmlValidator`; стили TOC в `styles.xml` (caps, шрифт, размер, табуляция); название из `content`; скрытый уровень не в `\o`; те же классы в HTML. Снимок из Word вручную (TESTPLAN).

### 12. Внешние рамки таблицы с классом
- **Что видно.** Рамка таблицы в DOCX берётся из общего вида `Sheet.Table` (`Inner`/`Outer`), а правило для таблицы с `outputclass` — это производный стиль, и `tblBorders` в нём, судя по коду (`CellBordersFor` использует только `Sheet.Table.Inner`), на внешнюю рамку не влияет.
- **Делаем.** Сначала воспроизвести: `table.custom { border: 2px solid red }`, `.custom { border-top-color… }`, `table.custom td { … }`. Затем: внешняя рамка (`border*` на `table`) → `tblBorders` стиля таблицы класса; внутренние (`td/th/entry` border) → `tcBorders`; приоритет по специфичности как у остального каскада; `frame`/`rowsep`/`colsep` в DITA не теряются.
- **?** Пришлите фрагмент CSS и таблицу, где не получилось — повторим точно.
- **Проверка.** DOCX проверяется по XML (`tblBorders` с цветом/толщиной) и `CheckValidDocx`; сравнение с HTML.

### 9. Шаблон DOCX
- **Что видно.** Сборка создаёт пакет с нуля (`DocxPublisher`, `AddStyles`, `AddNumbering`, `AddSettings`), шаблона нет.
- **Делаем.** Новый параметр проекта `.ditastudio-docx` → «Шаблон…» (`.docx`/`.dotx`): публикация открывает копию шаблона и очищает тело, сохраняя стили, нумерацию, темы, колонтитулы и параметры страницы (`sectPr`, `settings`). Порядок слоёв: **шаблон → стили, которых в нём нет (из каталога) → CSS проекта** (CSS главнее, как «помимо css» в замечании).
  - Стили: если стиль каталога (`Heading1`, `TOC1`, `TableCaption`…) есть в шаблоне — не затираем его, а CSS поверх; если нет — добавляем наш.
  - Колонтитулы и титул: из шаблона, если они там есть и диалог/CSS не заданы; иначе наши.
  - Маркеры списков, закладки, нумерация заголовков: свои `abstractNum` дописываются в нумерацию шаблона (id без пересечения).
  - Ошибки: повреждённый или защищённый шаблон — предупреждение и сборка без шаблона.
- **?** Что должен брать шаблон — только стили или ещё поля страницы, колонтитулы, титул с логотипом?
- **Проверка.** Тест со стилями шаблона (шрифт, цвет `Heading1` из шаблона — в выходе; CSS поверх меняет); `CheckValidDocx`; шаблон с колонтитулом и без; повреждённый файл; обновление оглавления Word вручную.
