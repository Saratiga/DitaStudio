# Чек-лист функционального тестирования DITA Studio

Проверка через `tools/UiHarness` (см. `--help` там же), демо-проект
`samples/GuideSample`, при необходимости — сборный проект в scratchpad.
Каждый пункт — отдельный проверяемый сценарий, не порядок выполнения.

Разделы 1–15: happy path по каждой фиче. Раздел 16: комбинации фич. Раздел 17:
граничные/невалидные входы. Раздел 18: нагрузка. Раздел 19: гонки. Раздел 20:
мультипроектные сценарии. Раздел 21: персистентность настроек. Раздел 22:
совместимость среды. Раздел 23: регрессия ядра. Раздел 24: политика перепрогона.

## 1. Проект

- [ ] Открыть папку проекта — дерево `ProjectTree` заполняется.
- [ ] Недавние проекты — пункт появляется, повторно открывает тот же проект.
- [ ] Подключить проект-источник ключей… — ключи чужого проекта видны на вкладке «Ключи».
- [ ] Отключить все проекты-источники — внешние ключи пропадают.
- [ ] Подключить внешний DTD… — элементы специализации в палитре/валидаторе.
- [ ] Отключить внешний DTD.
- [ ] Создать документ… (Ctrl+N) — для каждого типа: concept/task/reference/glossentry/topic.
- [ ] Сохранить (Ctrl+S) / Сохранить всё (Ctrl+Shift+S) на нескольких изменённых вкладках.
- [ ] Закрыть вкладку (Ctrl+W), в т.ч. с несохранёнными изменениями (диалог подтверждения).
- [ ] Обновить (Rescan) после ручного изменения файлов на диске.
- [ ] Переименовать/переместить файл из дерева проекта — ссылки в карте/conref обновляются.
- [ ] Открыть пустую папку (нет ни одного .dita/.ditamap) — не падает, пустое дерево.
- [ ] Открыть папку без .ditamap вообще — карта/панель «Карта» не падает, показывает пусто.
- [ ] Открыть проект с файлом только для чтения (read-only атрибут) — сохранение даёт понятную ошибку, не молча теряет правки.
- [ ] Путь к проекту с пробелами, кириллицей, длиной >260 символов.
- [ ] Повреждённый (не-XML) `.ditaval`/`.ditastudio-*` сайдкар при открытии проекта — приложение не падает, сообщение или игнор с логом.
- [ ] `.ditastudio-references` со ссылкой на несуществующую папку — открытие проекта не падает.
- [ ] Проект, ссылающийся сам на себя через `.ditastudio-references` (A→A) и по циклу (A→B→A) — не зацикливается (флаг `allowReferencedProjects`).
- [ ] Переименование/удаление открытого файла снаружи (в проводнике) во время работы с ним в редакторе.

## 2. Карта (ditamap)

- [ ] Выбор карты в `MapSelector`, если карт несколько.
- [ ] + Топик / + Раздел — добавление topicref/topichead.
- [ ] ↑ / ↓ — перемещение узла карты.
- [ ] → / ← — вложение/развложение узла.
- [ ] ✕ — удаление узла карты.
- [ ] Drag-and-drop узла в `MapTreeView`.
- [ ] Двойной клик по узлу карты — открывает целевой топик.
- [ ] Таблица соответствий… (reltable) — создание/редактирование.
- [ ] topicref с `href` на несуществующий файл — не падает, видимая пометка «битая ссылка».
- [ ] Карта, ссылающаяся сама на себя через mapref (A→A, A→B→A) — не зацикливается при построении дерева/публикации.
- [ ] Drag-and-drop узла в его же потомка (попытка сделать родителя своим ребёнком) — отклоняется, не ломает дерево.
- [ ] Reltable с пустыми ячейками/без relcolspec — не падает.
- [ ] Удаление узла карты, на который ссылается keydef — использующие ключ topicref не крашатся, валидатор сообщает.
- [ ] ✕ на корневом узле карты / на последнем оставшемся узле.

## 3. Ключи

- [ ] Список ключей (`Key`/`Href`) отражает keydef из карты.
- [ ] Двойной клик по ключу — переход к определению.
- [ ] Подсказка про scoped keys показывается, когда применимо.
- [ ] Два keydef с одинаковым именем ключа (в одной карте / в разных подключённых проектах) — детерминированное поведение (какой побеждает), не крах.
- [ ] `keyref` на несуществующий ключ — валидатор ловит, автор-режим не падает при рендере.
- [ ] key без `href` (только keyword/текст) — `keyref` в пустом элементе подставляет текст, как по спецификации.
- [ ] `<uicontrol keyref="k">свой текст</uicontrol>` — свой текст не затирается (см. CLAUDE.md «Грабли»).

## 4. Документ — источник (XML)

- [ ] Открытие документа — исходный XML в AvalonEdit с подсветкой.
- [ ] Ручное редактирование, сохранение, повторное открытие — изменения сохранены.
- [ ] Невалидный XML при сохранении — сообщение об ошибке, файл не портится.
- [ ] Файл с BOM и без BOM — оба открываются и сохраняются без порчи кодировки.
- [ ] Файл в кодировке, отличной от UTF-8 (напр. windows-1251 с явным `encoding=`), — либо корректно читается, либо явная ошибка (не тихая порча текста).
- [ ] Документ с внутренним DOCTYPE/ENTITY (потенциальный XXE) — сущности не подгружают произвольные внешние файлы/URL без ведома пользователя.
- [ ] Очень большой XML-файл (десятки МБ / сотни тысяч строк) — открывается за разумное время, не виснет UI-поток.
- [ ] Пустой файл (0 байт) с расширением .dita — открытие даёт понятную ошибку, не краш.
- [ ] Файл с некорректным `class`-атрибутом (не по конвенции DITA) — не роняет DisplayKind-эвристику.

## 5. Документ — режим «Автор» (WYSIWYG)

- [ ] Блочные элементы (абзац, список, примечание, блок кода, таблица) — отдельные плашки.
- [ ] Фразовые элементы вложены (напр. `<b><image/></b>`) — не схлопываются, не теряют содержимое.
- [ ] Enter/Backspace/Tab внутри плашки — только валидные по контент-модели операции.
- [ ] Показывать имена элементов — переключатель меняет отображение тегов.
- [ ] Отмена структурного изменения (Ctrl+Alt+Z) / Повторить (Ctrl+Alt+Y).
- [ ] Обычный набор текста — Ctrl+Z самого RichTextBox, не через UndoStack.
- [ ] Документ вообще без содержимого в body (пустой `<conbody/>`) — плашки не падают на пустом дереве.
- [ ] Документ только с заголовком, без тела.
- [ ] Список с глубокой вложенностью (ul>li>ul>li>ul…, 5+ уровней).
- [ ] Таблица 1×1, таблица без заголовка, таблица с colspan/rowspan на границе.
- [ ] Вставка/удаление в позиции, где контент-модель это запрещает, — операция отклоняется, а не создаёт невалидный DITA молча.
- [ ] Копипаст текста с внешним форматированием (из Word/браузера) в плашку — не протаскивает чужой HTML/RTF как DITA-разметку.
- [ ] Очень длинный абзац без переносов (перфоманс переноса строк в RichTextBox).

## 6. Структура и палитра

- [ ] Вставка через палитру (двойной клик, фильтр по тексту) для нескольких типов узлов.
- [ ] Вставка через меню «_Вставка»: Абзац, списки, Примечание, Блок кода, Сноска, Таблица…, Изображение…, Перекрёстная ссылка….
- [ ] Форматирование: Полужирный, Курсив, Код в строке, Элемент интерфейса.
- [ ] Переместить вверх/вниз на первом/последнем элементе (граница списка).
- [ ] Удалить элемент, в т.ч. последний оставшийся дочерний узел родителя.
- [ ] Переименовать id… — обновляет id и все ссылки (conref/xref).
- [ ] Переименовать id на значение, уже занятое другим элементом, — конфликт отлавливается, не создаёт дубликат id молча.
- [ ] Вынести в conref… — создаёт фрагмент, заменяет исходный элемент ссылкой.
- [ ] conref на самого себя или цепочка conref→conref→…→исходный (цикл) — не зацикливает резолвер.
- [ ] Объединить ячейку со следующей/со строкой ниже — на краю таблицы (последняя колонка/строка) не падает.
- [ ] Разрыв страницы перед заголовком (печать) — влияет на PDF.
- [ ] Таблица: перенос с повтором шапки (печать).
- [ ] Отметить как изменённое (rev) — атрибут проставляется, снимается повторным вызовом.
- [ ] Дерево «Структура» (Outline) — навигация синхронизируется с редактором на документе без заголовков вообще.
- [ ] Вкладка «Атрибуты» — редактирование обязательного атрибута (удаление значения) отлавливается валидатором.
- [ ] Атрибут с недопустимым для контент-модели значением (enum) через панель атрибутов — валидатор ловит.

## 7. Track changes

- [ ] Пометить как вставленное/удалённое — `status="new"/"deleted"` + `tcauthor`/`tcdate`.
- [ ] Принять правку — вставленное остаётся, удалённое физически убирается.
- [ ] Отклонить правку — вставленное убирается, удалённое возвращается.
- [ ] Узел `status="deleted"` не проходит проверку содержимого до Accept/Reject, но не ломает документ.
- [ ] Вложенные правки: удаление родителя, у которого дочерний узел помечен как вставленный, — порядок Accept/Reject не портит дерево.
- [ ] Accept/Reject без выделения/без активной правки — команда не падает, ничего не делает.
- [ ] Track changes на узле, участвующем в conref (изменение в источнике conref) — резолвер не подхватывает `status="deleted"` контент как активный.
- [ ] Два подряд tracked-изменения на одном узле (insert, потом delete) — итоговое состояние детерминировано.

## 8. Валидация

- [ ] Проверить документ / Проверить проект (F7) — список с уровнем/сообщением/местом/файлом.
- [ ] Двойной клик по строке проблемы — переход к месту в документе.
- [ ] Схемные ошибки (недопустимый дочерний элемент/атрибут).
- [ ] Встроенные стилевые правила.
- [ ] Правило плагина добавляет предупреждения наравне со встроенными.
- [ ] Падение плагина при выполнении правила — превращается в Warning, не роняет проверку.
- [ ] Внешний DTD: элементы специализации проходят валидацию по загруженной модели.
- [ ] Один элемент одновременно нарушает схему, стилевое правило и правило плагина — все три проблемы в списке, ни одна не перекрывает другую.
- [ ] Проект с сотнями ошибок сразу — список не подвисает, прокрутка/сортировка работают.
- [ ] Проверка документа с circular conref — не зацикливает валидатор.
- [ ] Проверка документа с несохранёнными изменениями в редакторе — валидирует актуальное состояние в памяти, а не последнюю сохранённую версию на диске (или явно наоборот — поведение должно быть задокументировано, не случайным).

## 9. Поиск и замена

- [ ] Найти в проекте (Ctrl+Shift+F) — список результатов с контекстом.
- [ ] «искать имена элементов» — поиск по именам тегов.
- [ ] «регулярное выражение» — поиск по regex.
- [ ] Двойной клик по результату — переход к найденному месту.
- [ ] Заменить всё — только для обычного текстового поиска, проверить итог на диске.
- [ ] Пустая строка поиска — не возвращает «весь проект» как совпадение, не падает.
- [ ] Невалидный regex (незакрытая группа) — понятная ошибка, не краш.
- [ ] Regex с катастрофическим backtracking (`(a+)+b` на длинной строке без `b`) — не подвешивает UI навсегда.
- [ ] Замена, в результате которой получается невалидный XML (напр. текст с `<`/`&` без экранирования) — экранируется корректно или отклоняется.
- [ ] Поиск/замена в документе, открытом с несохранёнными изменениями, — результат согласован с тем, что реально попадёт на диск.

## 10. Сравнение (diff)

- [ ] Сравнить файлы… — произвольная пара, XML-diff.
- [ ] Сравнить с последним коммитом (git).
- [ ] Сравнить с версией BASE (svn), либо пропуск при отсутствии svn в среде.
- [ ] Diff-окно закрывается штатно, не блокирует основное окно.
- [ ] Файл, не отслеживаемый git/svn (новый, не в индексе), — понятное сообщение, не краш.
- [ ] Первый коммит в репозитории (нет родителя) — «сравнить с HEAD» не падает.
- [ ] Файл с конфликт-маркерами merge (`<<<<<<<`) — diff не путает их с DITA-разметкой.
- [ ] Бинарный/не-XML файл по ошибке выбран для сравнения — понятная ошибка.

## 11. Публикация

- [ ] Собрать сайт HTML (F5) — весь проект/карта, ссылки между топиками рабочие.
- [ ] Собрать один HTML — единый файл документа/карты.
- [ ] Экспорт в PDF — файл открывается, пагинация корректная.
- [ ] Экспорт в DOCX — файл открывается, стили применены.
- [ ] Публикация плагином — выбор через `Dialogs.PickOne` при нескольких плагинах.
- [ ] Падение плагина публикации не роняет приложение.
- [ ] Условия сборки (ditaval) — чекбоксы исключений влияют на итог.
- [ ] Подключить/Редактировать .ditaval — flag-правила не затираются.
- [ ] Пользовательский CSS — каскад поверх встроенных стилей.
- [ ] Колонтитулы PDF — текст появляется в экспортированном PDF.
- [ ] Журнал сборки отражает ход и результат.
- [ ] Публикация пустой карты (0 topicref) — не падает, пустой но валидный вывод.
- [ ] Топик с битой ссылкой на изображение (`<image href="нет-такого.png">`) — публикация не падает, есть предупреждение.
- [ ] Публикация с несохранёнными изменениями в открытых вкладках — либо публикует сохранённую версию с явным предупреждением, либо публикует актуальную in-memory — поведение однозначное.
- [ ] Публикация проекта с сотнями топиков — время и память в разумных пределах.
- [ ] Имена файлов/путей с не-ASCII символами в выходе HTML/PDF/DOCX.
- [ ] Повторная публикация в тот же выходной путь поверх предыдущего результата — старые файлы не остаются «осиротевшими» (напр. удалённый topicref).
- [ ] Отмена/закрытие приложения посреди долгой публикации — не оставляет повреждённый частично записанный файл поверх старого валидного.

## 12. Предпросмотр (DocumentPane)

- [ ] HTML — рендер как есть.
- [ ] PDF — печать во временный файл, показ через WebView2 PDF-viewer, пагинация видна.
- [ ] DOCX-приближённо — тот же HTML со скином `WordPreviewCss`.
- [ ] Смена условий сборки/CSS отражается в предпросмотре после обновления.
- [ ] Открыть предпросмотр в браузере дожидается генерации перед открытием.
- [ ] Индикатор статуса показывает состояние генерации (в процессе/готово/ошибка).
- [ ] Быстрое повторное переключение формата (HTML→PDF→DOCX→HTML) до завершения предыдущей генерации — итоговый показанный формат соответствует последнему выбору (`_previewRequestId` реально защищает).
- [ ] Закрытие вкладки документа во время идущей генерации предпросмотра — не падает, не оставляет запущенный WebView2-процесс.
- [ ] Предпросмотр документа с ошибками валидации — не падает, показывает что может.
- [ ] Предпросмотр при недоступном WebView2 Evergreen Runtime — понятное сообщение, не необработанное исключение.

## 13. XLIFF (локализация)

- [ ] Экспорт в XLIFF — сегменты соответствуют фразовому/блочному содержимому.
- [ ] Импорт перевода — текст подставляется, bpt/ept/ph восстанавливаются без потери несегментных детей (`<alt>` и т.п.).
- [ ] id вне диапазона в импортируемом XLIFF — предупреждение, тег и содержимое пропускаются, не падает.
- [ ] Импорт XLIFF, экспортированного сторонним инструментом (не своим экспортёром) — либо корректно импортируется, либо явный отказ с причиной, не тихая порча документа.
- [ ] Пустой `<target>` в trans-unit — не подставляет пустоту поверх непереведённого текста без предупреждения (или подставляет по явному правилу).
- [ ] Дублирующиеся id trans-unit в одном XLIFF — детерминированное поведение, не крах.
- [ ] Текст с CJK/RTL/эмодзи через полный цикл экспорт→перевод→импорт — кодировка и направление не портятся.
- [ ] XLIFF с лишними/незнакомыми элементами/атрибутами (из другого инструмента) — игнорируются, не роняют парсер.

## 14. Плагины

- [ ] Плагин из `plugins/` подхватывается при старте без пересборки хоста.
- [ ] Правило валидации плагина отображается в списке проблем.
- [ ] Формат публикации плагина доступен в диалоге выбора.
- [ ] Команда плагина режима «Автор» выполняется над текущим документом.
- [ ] Исключение внутри любого из трёх видов плагина — не роняет приложение, есть сообщение.
- [ ] Абстрактный/невалидный тип в сборке плагина не подхватывается, не роняет загрузку остальных типов из той же папки.
- [ ] Два плагина одного контракта одновременно в `plugins/` — оба видны в `Dialogs.PickOne`.
- [ ] Плагин, собранный против несовместимой версии `DitaStudio.Core.dll` (другая сигнатура интерфейса), — понятная ошибка загрузки, не краш хоста.
- [ ] .dll в `plugins/`, вообще не содержащая ни одного из трёх интерфейсов, — игнорируется молча/с логом, не ошибка.
- [ ] Добавление нового плагина в `plugins/` без перезапуска приложения — ожидаемо не подхватывается (загрузка только при старте) — зафиксировать, не тестировать как баг.
- [ ] Удаление/блокировка .dll плагина между сборкой и стартом (файл занят антивирусом) — понятная ошибка, не краш.

## 15. Общее приложение

- [ ] Тёмная тема — применяется сразу, чекбокс отражает состояние.
- [ ] Об элементе под курсором (F1) — контекстная справка.
- [ ] О программе — открывается/закрывается.
- [ ] Множественные вкладки — переключение не путает Undo/Attributes/Outline между документами.
- [ ] Выход при несохранённых изменениях — запрашивает подтверждение.
- [ ] Смена темы с открытым модальным диалогом — диалог не остаётся в старой теме/не рвётся визуально.
- [ ] `%APPDATA%\DitaStudio` недоступен для записи (права/диск полон) — запуск не падает, просто не сохраняет недавние проекты.
- [ ] Два одновременных запуска `DitaStudio.exe` — независимые окна, либо явная защита от повторного запуска; не портят общий `.ditastudio-*` файл гонкой.
- [ ] Изменение размера/сворачивание/максимизация главного окна — layout не ломается на минимальном размере.

## 16. Комбинации фич (интеграционные сценарии)

Каждая фича по отдельности может работать, а вместе — нет. Матрица важных пересечений:

- [ ] Track changes + XLIFF: экспорт документа с `status="new"/"deleted"` узлами — удалённый текст либо не попадает в сегменты, либо явно помечен.
- [ ] Track changes + conref: правка в источнике conref, принятие/отклонение не рвёт целевые ссылки.
- [ ] Условия сборки (.ditaval) + внешний DTD: специализированные элементы корректно исключаются/флагуются по `@class`.
- [ ] Условия сборки + предпросмотр DOCX-приближённо: исключённый контент не появляется ни в HTML, ни в DOCX-скине.
- [ ] Плагин-правило валидации + встроенное правило на одном и том же узле — оба сообщения присутствуют одновременно.
- [ ] Плагин формата публикации + условия сборки — плагин получает уже отфильтрованное дерево, а не полное.
- [ ] Плагин формата публикации + внешний DTD — плагин видит элементы специализации через общий `ElementDef`, не падает на незнакомом `DisplayKind`.
- [ ] Переименовать id + conref, ссылающийся на этот id, + track changes на той же ветке — все три операции подряд не рассинхронизируют документ.
- [ ] Экспорт в XLIFF → импорт перевода → повторная публикация HTML/PDF/DOCX — переведённый текст доходит до всех трёх форматов.
- [ ] Поиск/замена по всему проекту в документе, который сейчас открыт в режиме «Автор» с несохранёнными изменениями, — итог на диске согласован с тем, что видно в редакторе.
- [ ] Подключённый проект-источник ключей + внешний DTD одновременно в двух разных проектах — конфликт специализаций (см. раздел 20) не путается с конфликтом ключей.

## 17. Граничные и невалидные входы (устойчивость/безопасность)

- [ ] DTD с XXE-подобной внешней сущностью (`<!ENTITY x SYSTEM "file:///...">`) — `DtdReader` не подгружает произвольные локальные/сетевые ресурсы без ведома пользователя.
- [ ] DTD с рекурсивным раскрытием параметрических сущностей (billion laughs — сущность ссылается сама на себя или взрывной рост) — есть предел, не OOM/не зависание.
- [ ] Href/conref со значением `../../../../etc/something` (path traversal за пределы проекта) — резолвер не читает/не пишет произвольно за пределами ожидаемой области, либо явно предупреждает.
- [ ] Глубоко вложенный XML (тысячи уровней вложенности) — рекурсивные обходы (`ModelAutomaton`, `XliffConverter.WalkForExport`, `InlineEditor.AppendChildren`) не переполняют стек.
- [ ] Документ с элементом, которого нет ни в основном каталоге, ни в подключённом DTD, — валидатор/автор-режим сообщают «неизвестный элемент», не падают.
- [ ] `.ditaval` с несуществующим/некорректным значением `action` (не exclude/include/flag/passthrough) — игнорируется с предупреждением, не крашит парсер.
- [ ] Циклический conref (A conref на B, B conref на A) — резолвер обнаруживает цикл, не зацикливается бесконечно.
- [ ] Циклическая карта (mapref сам на себя, транзитивно) — построение дерева карты не зацикливается.
- [ ] Файл проекта с NTFS-зарезервированными именами (`CON`, `PRN`, `aux.dita`) — на Windows это ловушка сама по себе, проверить, что редактор не падает при попытке открыть/создать такое.
- [ ] Огромный одиночный DITA-файл (сотни МБ) — открытие либо укладывается в разумное время, либо явно отказывает с понятным сообщением (не безлимитный OOM).

## 18. Нагрузка и производительность

- [ ] Проект с 500+ топиками — время построения дерева проекта/карты, поиск по проекту, публикация сайта — все в разумных пределах.
- [ ] Документ с тысячами дочерних узлов в одном body — прокрутка режима «Автор» не подвисает.
- [ ] Повторная публикация (HTML+PDF+DOCX) 20+ раз подряд — память процесса не растёт неограниченно (утечка WebView2/временных файлов).
- [ ] Открытие/закрытие 50+ вкладок подряд — память освобождается, UI не деградирует по отзывчивости.
- [ ] Валидация проекта с тысячами файлов — прогресс виден, не выглядит зависшим.
- [ ] Поиск по проекту с большим количеством совпадений (тысячи) — список результатов не подвешивает UI.

## 19. Конкурентность и гонки

- [ ] Двойной быстрый клик на «Собрать сайт HTML»/«Экспорт в PDF» — второй запуск не стартует параллельно первому (либо оба безопасно завершаются, без гонки за один файл).
- [ ] Сохранение документа (Ctrl+S) в момент, когда файл на диске только что изменён снаружи, — либо предупреждение о конфликте, либо детерминированный «последний записавший побеждает», не порча файла.
- [ ] Переключение формата предпросмотра несколько раз подряд быстрее, чем генерируется предыдущий (уже в разделе 12, продублировать здесь как гоночный, не только UI-сценарий).
- [ ] Валидация проекта (F7), запущенная повторно до завершения предыдущей, — не приводит к дублирующимся/перепутанным записям в списке проблем.
- [ ] Закрытие приложения во время фоновой публикации/экспорта — не оставляет заблокированные временные файлы (PDF/HTML), которые мешают следующему запуску.

## 20. Мультипроектные и мультиэкземплярные сценарии

- [ ] Два проекта открыты в разных вкладках/окнах с конфликтующими внешними DTD — последний загруженный побеждает в общем `DitaCatalog.Default` (задокументированное ограничение) — проверить, что это именно тихая подмена, а не крах.
- [ ] Тот же проект открыт одновременно в двух запущенных процессах `DitaStudio.exe` — сохранение из одного не роняет другой процесс при следующем сохранении/rescan.
- [ ] Проект A подключает проект B как источник ключей, проект B параллельно открыт и редактируется — обновление ключей у A подхватывается по Rescan, не раньше и не с крашем.

## 21. Персистентность настроек (`.ditastudio-*`)

- [ ] Ручное редактирование `.ditastudio-ditaval`/`-external-dtd`/`-references`/`-css`/`-conditions`/`-pdf-header` снаружи, затем открытие проекта — новые значения подхватываются.
- [ ] Удаление одного из этих файлов вручную — проект открывается с настройками по умолчанию для этой опции, не падает.
- [ ] Файл в неожиданном формате (не тот, что пишет сам `DitavalWriter`/аналоги) — либо разбирается толерантно, либо явная ошибка при открытии проекта.
- [ ] Проект, созданный/помеченный более ранней версией приложения (гипотетически другой формат сайдкара), — не должен молча терять настройки без сообщения.

## 22. Совместимость среды

- [ ] Масштаб экрана 100%/125%/150%/200% (DPI) — координаты кликов/областей рендера не съезжают (см. `SetProcessDpiAwarenessContext` в UiHarness — то же должно быть верно и для самого приложения).
- [ ] Тёмная/светлая системная тема Windows — приложение не обязано следовать системной, но не должно визуально ломаться в любой из них.
- [ ] Запуск при отсутствующем WebView2 Evergreen Runtime — понятное сообщение при первом обращении к предпросмотру/PDF/сравнению, не необработанное исключение при старте.
- [ ] Английская локаль ОС при русском UI приложения — форматы дат/чисел в атрибутах (`tcdate` и т.п.) не зависят от локали пользователя.
- [ ] Минимальный поддерживаемый размер главного окна — все панели остаются доступны (через скролл/сворачивание), не обрезаются без возможности прокрутки.
