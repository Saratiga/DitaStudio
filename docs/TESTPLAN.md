# Чек-лист функционального тестирования DITA Studio

Проверка через `tools/UiHarness` (см. `--help` там же), демо-проект
`samples/GuideSample`, при необходимости — сборный проект в scratchpad.
Каждый пункт — отдельный проверяемый сценарий, не порядок выполнения.

## 1. Проект

- [ ] Открыть папку проекта (Файл → Открыть папку проекта…) — дерево `ProjectTree` заполняется.
- [ ] Недавние проекты — пункт меню появляется после открытия, повторно открывает тот же проект.
- [ ] Подключить проект-источник ключей… — ключи чужого проекта видны на вкладке «Ключи».
- [ ] Отключить все проекты-источники — внешние ключи пропадают.
- [ ] Подключить внешний DTD… — элементы специализации появляются в палитре/валидаторе.
- [ ] Отключить внешний DTD.
- [ ] Создать документ… (Ctrl+N) — для каждого типа: concept/task/reference/glossentry/topic.
- [ ] Сохранить (Ctrl+S) / Сохранить всё (Ctrl+Shift+S) на нескольких изменённых вкладках.
- [ ] Закрыть вкладку (Ctrl+W), в т.ч. с несохранёнными изменениями (диалог подтверждения).
- [ ] Обновить (Rescan) после ручного изменения файлов на диске.
- [ ] Переименовать / переместить файл… из контекстного меню дерева проекта — ссылки на файл в карте/conref обновляются.

## 2. Карта (ditamap)

- [ ] Выбор карты в `MapSelector`, если карт несколько.
- [ ] + Топик / + Раздел — добавление topicref/topichead.
- [ ] ↑ / ↓ — перемещение узла карты.
- [ ] → / ← — вложение/развложение узла.
- [ ] ✕ — удаление узла карты.
- [ ] Drag-and-drop узла в `MapTreeView`.
- [ ] Двойной клик по узлу карты — открывает целевой топик.
- [ ] Таблица соответствий… (reltable) — создание/редактирование.

## 3. Ключи

- [ ] Список ключей (`Key`/`Href`) отражает keydef из карты.
- [ ] Двойной клик по ключу — переход к определению.
- [ ] Подсказка про области видимости ключей (scoped keys) показывается, когда применимо.

## 4. Документ — источник (XML)

- [ ] Открытие документа показывает исходный XML в AvalonEdit с подсветкой.
- [ ] Ручное редактирование XML, сохранение, повторное открытие — изменения сохранены.
- [ ] Невалидный XML при сохранении — сообщение об ошибке, файл не портится.

## 5. Документ — режим «Автор» (WYSIWYG)

- [ ] Блочные элементы (абзац, список, примечание, блок кода, таблица) отображаются отдельными плашками.
- [ ] Фразовые элементы (bold/italic/code/uicontrol) — вложенные комбинации, включая элемент внутри
      фразового (например `<b><image/></b>`), не схлопываются и не теряют содержимое.
- [ ] Enter/Backspace/Tab внутри плашки — структурные операции проходят валидацию контент-модели,
      получить невалидный DITA через клавиатуру нельзя.
- [ ] Показывать имена элементов — переключатель меняет отображение тегов.
- [ ] Отмена структурного изменения (Ctrl+Alt+Z) / Повторить (Ctrl+Alt+Y).
- [ ] Обычный набор текста отменяется штатным Ctrl+Z самого RichTextBox (не через UndoStack).

## 6. Структура и палитра

- [ ] Вставка элемента через палитру (двойной клик, фильтр по тексту) для нескольких типов узлов.
- [ ] Вставка через меню «_Вставка»: Абзац, Маркированный список, Нумерованный список, Примечание,
      Блок кода, Сноска, Таблица…, Изображение…, Перекрёстная ссылка….
- [ ] Форматирование: Полужирный (Ctrl+B), Курсив (Ctrl+I), Код в строке, Элемент интерфейса.
- [ ] Переместить вверх/вниз, Удалить элемент.
- [ ] Переименовать id… — обновляет id и все ссылки (conref/xref) на элемент.
- [ ] Вынести в conref… — создаёт переиспользуемый фрагмент, заменяет исходный элемент ссылкой.
- [ ] Объединить ячейку со следующей / со строкой ниже (таблицы).
- [ ] Разрыв страницы перед заголовком (печать) — переключатель, влияет на PDF.
- [ ] Таблица: перенос с повтором шапки (печать) — переключатель.
- [ ] Отметить как изменённое (rev) — атрибут `rev` проставляется.
- [ ] Дерево «Структура» (Outline) — навигация по документу, выбор узла синхронизируется с редактором.
- [ ] Вкладка «Атрибуты» — показывает атрибуты выбранного элемента, редактирование применяется.

## 7. Track changes

- [ ] Пометить как вставленное / как удалённое — `status="new"`/`"deleted"` + `tcauthor`/`tcdate`.
- [ ] Принять правку — вставленное остаётся, удалённое физически убирается из дерева.
- [ ] Отклонить правку — вставленное убирается, удалённое возвращается в обычное состояние.
- [ ] Узел с `status="deleted"` не проходит валидацию содержимого до Accept/Reject, но не ломает документ.

## 8. Валидация

- [ ] Проверить документ (текущий) — список проблем в «Проверка» с уровнем/сообщением/местом/файлом.
- [ ] Проверить проект (F7) — агрегирует проблемы по всем файлам.
- [ ] Двойной клик по строке проблемы — переход к месту в документе.
- [ ] Схемные ошибки (недопустимый дочерний элемент/атрибут) отлавливаются.
- [ ] Стилевые правила редактора (встроенные) отлавливаются.
- [ ] Правило плагина (`IValidationRulePlugin`) добавляет предупреждения наравне со встроенными.
- [ ] Падение плагина при выполнении правила не роняет проверку — превращается в Warning.
- [ ] Внешний DTD: элементы специализации проходят валидацию по загруженной модели.

## 9. Поиск и замена

- [ ] Найти в проекте… (Ctrl+Shift+F) — обычный текстовый поиск, список результатов с контекстом.
- [ ] «искать имена элементов» — поиск по именам тегов, а не по тексту.
- [ ] «регулярное выражение» — поиск по regex.
- [ ] Двойной клик по результату — переход к найденному месту.
- [ ] Заменить всё — только для обычного текстового поиска (не regex/не по именам), проверить итог на диске.

## 10. Сравнение (diff)

- [ ] Сравнить файлы… — произвольная пара файлов, показывает XML-diff.
- [ ] Сравнить с последним коммитом (git) — репозиторий с git, есть предыдущий коммит.
- [ ] Сравнить с версией BASE (svn) — репозиторий с svn (или пропустить, если svn недоступен в среде).
- [ ] Diff-окно закрывается штатно, не блокирует основное окно.

## 11. Публикация

- [ ] Собрать сайт HTML… (F5) — весь проект/карта, ссылки между топиками рабочие.
- [ ] Собрать один HTML… — единый файл документа/карты.
- [ ] Экспорт в PDF… — через WebView2 печать, файл открывается, пагинация корректная.
- [ ] Экспорт в DOCX… — файл открывается в Word/совместимом приложении, стили применены.
- [ ] Публикация плагином… — `IPublishFormatPlugin`, выбор через `Dialogs.PickOne` при нескольких плагинах.
- [ ] Падение плагина публикации не роняет приложение — сообщение об ошибке.
- [ ] Условия сборки… (ditaval) — чекбоксы исключений, влияют на итоговую публикацию.
- [ ] Подключить .ditaval… — привязка внешнего файла к проекту.
- [ ] Редактировать .ditaval… — правка exclude-правил через тот же UI, flag-правила не затираются.
- [ ] Пользовательский CSS… — применяется в HTML/предпросмотре, каскад поверх встроенных стилей.
- [ ] Колонтитулы PDF… — текст колонтитулов появляется в экспортированном PDF.
- [ ] Журнал сборки — отражает ход и результат последней публикации.

## 12. Предпросмотр (DocumentPane)

- [ ] Переключатель формата: HTML — рендер как есть.
- [ ] Переключатель формата: PDF — реальная печать во временный файл, показ через WebView2 PDF-viewer,
      пагинация видна.
- [ ] Переключатель формата: DOCX-приближённо — тот же HTML со скином `WordPreviewCss`.
- [ ] Переключение условий сборки / пользовательского CSS отражается в предпросмотре после обновления.
- [ ] Открыть предпросмотр в браузере — дожидается генерации перед открытием (гонка `_previewRequestId`).
- [ ] Индикатор статуса предпросмотра показывает состояние генерации (в процессе/готово/ошибка).

## 13. XLIFF (локализация)

- [ ] Экспорт в XLIFF… — по одному документу, сегменты соответствуют фразовому/блочному содержимому.
- [ ] Импортировать перевод из XLIFF… — текст сегментов подставляется обратно, вложенность
      фразовых элементов (bpt/ept/ph) восстанавливается без потери несегментных детей (напр. `<alt>`).
- [ ] id вне диапазона в импортируемом XLIFF — предупреждение, тег и содержимое пропускаются, не падает.

## 14. Плагины

- [ ] Плагин из `plugins/` рядом с exe подхватывается при старте без пересборки хоста.
- [ ] Правило валидации плагина отображается в списке проблем.
- [ ] Формат публикации плагина доступен в диалоге выбора.
- [ ] Команда плагина режима «Автор» (меню «_Структура» → «Команда плагина…») выполняется над текущим документом.
- [ ] Исключение внутри любого из трёх видов плагина — приложение не падает, есть сообщение.
- [ ] Абстрактный/невалидный тип в сборке плагина не подхватывается загрузчиком (не роняет загрузку остальных).

## 15. Общее приложение

- [ ] Тёмная тема — переключатель в меню «_Справка», применяется сразу, чекбокс отражает состояние.
- [ ] Об элементе под курсором (F1) — контекстная справка по DITA-элементу.
- [ ] О программе — диалог открывается и закрывается.
- [ ] Множественные вкладки документов, переключение между ними не путает состояние Undo/Attributes/Outline.
- [ ] Выход — при несохранённых изменениях запрашивает подтверждение.

## Известные ограничения (не баг, см. CLAUDE.md «Что осталось незакрытым»)

Не проверять как дефект, а зафиксировать как ожидаемое поведение:
живая правка alt-текста только через исходник; PDF без своего движка (только печать
HTML); WebView2 обязателен, без запасного пути; внешний DTD общий на сеанс, не
per-project; проверяется только орфография, не грамматика; XLIFF — только по
одному документу; git/svn — просмотр diff без коммита из редактора; совместного
редактирования нет.
