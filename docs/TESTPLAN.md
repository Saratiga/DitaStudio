# Чек-лист функционального тестирования DITA Studio

Проверка через `tools/UiHarness` (см. `--help` там же), демо-проект
`samples/GuideSample`, при необходимости — сборный проект в scratchpad.
Каждый пункт — отдельный проверяемый сценарий, не порядок выполнения.

Чек-лист общий для основной версии (Avalonia, `src/DitaStudio.Desktop`) и легаси-версии WPF
(`src/DitaStudio.App`); пункты, относящиеся только к одной из них, помечены. Основную версию
прогонять на Windows, Linux и macOS (раздел 25).

Автоматизированные подмножества:
- Avalonia — `tests/DitaStudio.Desktop.Tests` (Avalonia.Headless, без экрана, в CI на Linux):
  открытие проекта, документ, палитра, сохранение и отмена, исходный код и автодополнение,
  режим «Автор» (клавиши, разделение с разметкой, смешанное содержимое, частичная
  перестройка), орфография, паритет с WPF (все пункты меню и подсказки кнопок, сценарии
  UI-тестов WPF), снимки окон в обеих темах; встроенный Chromium — `CefPreviewTests` под
  `xvfb-run` с `DITASTUDIO_CEF_TESTS=1` (печать PDF с колонтитулами, предпросмотр трёх форматов).
- WPF — xUnit-тесты в `tests/DitaStudio.UiTests` (`dotnet test tests\DitaStudio.UiTests`):
  запуск, открытие недавнего проекта, диалоги «О программе» и «Оформление DOCX».

Это быстрая проверка на CI/PR, не замена полного ручного прогона. См. CLAUDE.md, раздел «UI-тесты и UiHarness», про известное
ограничение FlaUI/UIA3 (содержимое вкладок TabControl не видно обходу автомейшн-дерева) —
проверки, которым нужен доступ к ProjectTree/палитре/дереву карты и т.п., пока
только через ручной прогон или `tools/UiHarness` вручную с `clickat`/скриншотом.

Разделы 1–15: happy path по каждой фиче. Раздел 16: комбинации фич. Раздел 17:
граничные/невалидные входы. Раздел 18: нагрузка. Раздел 19: гонки. Раздел 20:
мультипроектные сценарии. Раздел 21: персистентность настроек. Раздел 22:
совместимость среды. Раздел 23: регрессия ядра. Раздел 24: политика перепрогона.
Раздел 25: кроссплатформенность.

## 1. Проект

- [ ] Открыть папку проекта — дерево `ProjectTree` заполняется.
- [ ] Недавние проекты — пункт появляется, повторно открывает тот же проект.
- [ ] Открыть вторую папку проекта — она появляется в дереве вторым корнем, вкладки первого проекта остаются, в заголовке окна — название активного проекта; у вкладок документов и карт после имени файла — название проекта.
- [ ] Открыть тот же проект ещё раз — второго корня нет, проект просто становится активным.
- [ ] Одноимённый топик в двух проектах — две вкладки; переключение вкладки меняет активный проект (заголовок окна, список ключей, вкладка «Карта»); у проекта с внешним DTD каталог элементов свой.
- [ ] Вкладка «Карта»: у каждого проекта своя вкладка карты; ПКМ → «Закрыть» и «Закрыть остальные»; «＋ Карта» открывает другую карту активного проекта.
- [ ] «Файл → Закрыть проект» / меню дерева → «Закрыть проект»: вкладки этого проекта закрываются (с вопросом о несохранённом, «Отмена» всё оставляет), второй проект и его вкладки остаются и становится активным.
- [ ] Подключить проект-источник ключей… — ключи чужого проекта видны на вкладке «Ключи».
- [ ] Отключить все проекты-источники — внешние ключи пропадают.
- [ ] Подключить внешний DTD… — элементы специализации в палитре/валидаторе.
- [ ] Отключить внешний DTD.
- [ ] Создать документ… (Ctrl+N) — для каждого типа: concept/task/reference/glossentry/topic.
- [ ] Сохранить (Ctrl+S) / Сохранить всё (Ctrl+Shift+S) на нескольких изменённых вкладках.
- [ ] Закрыть вкладку (Ctrl+W), в т.ч. с несохранёнными изменениями (диалог подтверждения).
- [ ] Обновить (Rescan) после ручного изменения файлов на диске.
- [ ] Переименовать/переместить файл из дерева проекта — ссылки в карте/conref обновляются.
- [ ] Открыть пустую папку (нет ни одного .dita/.ditamap) — не падает, пустое дерево.
- [ ] Открыть папку без .ditamap вообще — карта/панель «Карта» не падает, показывает пусто.
- [ ] Открыть проект с файлом только для чтения (read-only атрибут) — сохранение даёт понятную ошибку, не молча теряет правки.
- [ ] Путь к проекту с пробелами, кириллицей, длиной >260 символов.
- [ ] Повреждённый (не-XML) `.ditaval`/`.ditastudio-*` сайдкар при открытии проекта — приложение не падает, сообщение или игнор с логом.
- [ ] `.ditastudio-references` со ссылкой на несуществующую папку — открытие проекта не падает.
- [ ] Проект, ссылающийся сам на себя через `.ditastudio-references` (A→A) и по циклу (A→B→A) — не зацикливается (флаг `allowReferencedProjects`).
- [ ] Переименование/удаление открытого файла снаружи (в проводнике) во время работы с ним в редакторе.

## 2. Карта (ditamap)

- [ ] Выбор карты в `MapSelector`, если карт несколько.
- [ ] + Топик / + Раздел — добавление topicref/topichead.
- [ ] ↑ / ↓ — перемещение узла карты.
- [ ] → / ← — вложение/развложение узла.
- [ ] ✕ — удаление узла карты.
- [ ] Drag-and-drop узла в `MapTreeView`: середина строки — стать дочерним, верхняя/нижняя четверть — перед/после; линия или рамка показывает место; ветка-цель раскрывается; отмена (`Ctrl+Alt+Z`) — один шаг.
- [ ] Drag-and-drop: у верхнего и нижнего края длинной карты список плавно прокручивается; в середине и после переноса полоса прокрутки не «убегает» за строкой.
- [ ] Drag-and-drop в `bookmap`: `chapter` в `chapter` и глава перед `frontmatter` — «нельзя» с причиной в строке состояния.
- [ ] Строка вложенной карты (`mapref`): «Убрать из карты», «+ Раздел», перенос правят файл вложенной карты (вкладка помечена «•»), внешняя карта не меняется.
- [ ] Отмена правки карты (`Ctrl+Alt+Z`) — команды меню карты продолжают работать на текущих строках.
- [ ] Каскад CSS в DOCX: `ol > li:first-child { font-weight: bold }`, `note[type="warning"] { background-color: … }`, `tbody > row:nth-child(even) > entry { … }`, `p:not(.lead)`, `li::before { content: "▸ " }`, `table { width: 60% }` — в Word оформлены ровно те элементы, что и в HTML/PDF; в «Журнале сборки» селектор без совпадений назван предупреждением.
- [ ] Оформление контейнера: щелчок по рамке `note`/`section`, затем размер, цвет, выравнивание — `outputclass` на контейнере, абзацы внутри в «Авторе» меняются, в DOCX/HTML действует на весь текст; «Обычный» снимает.
- [ ] Колонтитул с логотипом: картинка 2000×500 и 100×100 при полях 20 мм — обе по высоте области колонтитула (флажок «Подгонять картинки» включён), не выходят за поле и не сдвигают текст; при выключенном флажке — заданная высота, но не шире текста. DOCX и PDF.
- [ ] CSS `@page { @top-right { content: string(title) } @bottom-center { content: "Стр. " counter(page) " из " counter(pages) } }`: в DOCX колонтитулы Word с полями PAGE/NUMPAGES («Обновить поля»), в PDF — те же; они перекрывают колонтитулы из диалога; цвет, размер, `border-bottom` видны; `content: none` убирает поле.
- [ ] «Оформление DOCX…» → «ОК» не сбрасывает свой размер листа, ориентацию и поля из «Параметров страницы…».
- [ ] Щелчок по пустому месту в «Авторе» снимает выделение текста и рамки блока; переход в другой блок снимает выделение текста в прежнем.
- [ ] Курсор клавишами уходит за экран (вниз по документу, в конец длинного абзаца) — полоса прокрутки следует за ним.
- [ ] Окно подсказки элементов растягивается за уголок, размер сохраняется между открытиями и после перезапуска.
- [ ] Д6: окно подсказки растягивается за **каждый** из четырёх углов (курсор меняется на диагональный); за левый/верхний угол окно едет за указателем, противоположный угол стоит на месте, без дрожания; длинные названия в списке переносятся.
- [ ] Д1: окна «Топик не найден», «Условия сборки», «Список продуктов», «Вставить таблицу», «Колонтитулы PDF», «Пользовательский CSS» — высота по содержимому, кнопки видны; на маленьком экране/при масштабе 200 % — полоса прокрутки, а не обрезание.
- [ ] Д2: в окнах «Что сделать со строкой», выбор плагина, «Вставить ссылку» двойной щелчок по строке выбирает её; щелчок по пустому месту и по полосе прокрутки — нет; `Enter` в списке — как «ОК».
- [ ] Стереть название рисунка или таблицы: в «Авторе» слева «Рисунок 1» (без точки), в DOCX/HTML/PDF — «Рисунок 1» без названия; «Подпись… добавить или убрать» удаляет `title` — подписи нет, номер не расходуется.
- [ ] ПКМ по топику в карте: «Размещать на новой странице» — в DOCX/PDF топик с новой страницы; «Не размещать» — перекрывает «каждый топик верхнего уровня — с новой страницы»; повторный выбор снимает; отмена (`Ctrl+Alt+Z`) возвращает.
- [ ] Вкладки: ПКМ → «Закрепить» — вкладка слева, 📌, без «✕», `Ctrl+W` её не закрывает; перезапуск проекта — закреплённые открываются сами; «Закрыть все», «Закрыть остальные», «Закрыть справа»; несохранённая вкладка — вопрос, «Отмена» останавливает.
- [ ] Красная строка карты: подсказка и строка состояния называют причину; двойной щелчок — окно «Создать файл / Выбрать другой файл… / Убрать строку», карта не открывается пустой; «Создать файл по ссылке» — строка перестаёт быть красной; «Выбрать другой файл…» меняет `href`.
- [ ] «Предпросмотр» топика с отсутствующей картинкой: плашка «Картинка не найдена: путь» вместо картинки, текст на месте.
- [ ] `Enter` в середине текста ячейки — два абзаца внутри той же ячейки, строка таблицы цела; в конце — меню «Новый абзац в ячейке / блоки в ячейке» без «entry» и «row».
- [ ] Размер «Другой…» (13,5 пт): класс `size-13_5`, в «Авторе» виден, в DOCX/HTML/PDF 13,5 пт; 3 и 500 ограничиваются.
- [ ] Д3: «А» на жёлтом на панели — палитра красный/жёлтый/зелёный/синий, «Другой цвет…», «Нет цвета»; с выделением закрашивает (в «Авторе» фон, текст читаем, на синем белый); без выделения — кнопка подсвечена, выделение мышью красит, Esc выключает; «ластик»; «Другой цвет…» — окно палитры и кода, неверный код → «Нужен код из шести цифр»; цвета в HTML/PDF; в DOCX открыть в Word: жёлтый/красный/зелёный/синий — «Цвет выделения текста» (его кнопка показывает цвет), свой — заливка; тёмный — белый текст.
- [ ] Д5а: протяжка мыши от текста одного блока к тексту другого (вниз и вверх) — блоки между ними обводятся целиком, текст не выделен; у края окна «Автор» прокручивается; возврат указателя в начальный блок — снова выделение текста; Shift+щелчок продолжает диапазон; абзац внутри заметки → абзац за ней = заметка целиком + абзац; из ячейки в соседнюю ячейку блоки не выделяются; Delete/Backspace удаляют все (одна отмена «Удаление блоков: N»), Esc снимает, Enter открывает «Обернуть в…», правая кнопка по выделению — меню.
- [ ] Копирование блоков: выделить 2–3 блока, Ctrl+C, выделить другой блок, Ctrl+V — копии встали после него, выделены; повторные `id` заменены на `…-копия`; Ctrl+X — блоки ушли, Ctrl+V в другое место вернул; Ctrl+V с курсором в абзаце (в буфере блоки) вставляет блоки после абзаца, а Ctrl+V после копирования обычного текста вставляет текст; пункты списка после абзаца в теле — «Сюда эти блоки вставить нельзя», а после пункта — в тот же список; вставка из буфера в другую вкладку и в «Исходный код» (как XML); отмена возвращает одним шагом.
- [ ] Д5б: «Структура → Обернуть в…», правая кнопка в блоке и по выделению: в списке только допустимые обёртки (для абзацев note/section/div/fig/example…, для пунктов списка — нет note/div); выбор оборачивает, порядок блоков сохранён, обёртка выделена, отмена возвращает; фильтр по `<note>`; без выделения — оборачивается блок под курсором; результат проходит проверку проекта без ошибок структуры.
- [ ] Д10: протяжка от ячейки к ячейке — подсвечен прямоугольник, текст не выделен; в объединённую ячейку прямоугольник расширяется; Shift+щелчок; возврат в начальную ячейку — текст; «Выделить строку/столбец»; Delete очищает, Esc снимает; ПКМ на выделении — меню (вставить/удалить строки и столбцы по числу выделенного, объединить, разделить, очистить, выровнять, границы); значки панели (строки, столбцы, объединить, выравнивание) работают на выделении; объединить через шапку/тело или опустошив строку — отказ.
- [ ] Д11: значок «Границы» и «Структура → Таблица → Границы выделенных ячеек» — пункты как в Word; нижняя/верхняя/левая/правая, внешние, внутренние, внутренняя горизонтальная/вертикальная переключаются; «Нет границы»; край таблицы у части стороны — сообщение; верх всей ширины снимается, остальная рамка остаётся (в «Авторе», HTML, PDF и открытом в Word DOCX), классы `frame-…` в `outputclass`; «Все границы» таблицы сбрасывает их.
- [ ] Д4: щелчок по рамке/подписи абзаца, примечания, рисунка, блока кода, списка, XML-комментария — контур; `Backspace`/`Delete` удаляют (одна отмена возвращает), `Esc` снимает; у выделенной ячейки `Delete` очищает её, ячейка остаётся. Тест `SelectedBlock_DeletedWithKey_ForEveryBlockElementOfCatalog` перебирает все блочные элементы каталога.
- [ ] Д8: щелчок в текст ячейки таблицы (у верхнего и нижнего края окна тоже) полосу прокрутки не двигает; переход Tab/стрелками по-прежнему прокручивает к курсору.
- [ ] Д9: в ячейке два абзаца, абзац со списком, примечание — в экспортированном DOCX каждый блок отдельным абзацем (в простой таблице тоже); текст ячейки без блоков — один абзац как раньше; PDF и HTML — блоки отдельно.
- [ ] Д13: «Дублировать» строку карты, «Удалить файл…» на одной из двух строк — уходит одна, файл и вторая остаются; на последней — файл удаляется с диска.
- [ ] Таблица: щелчок по полю над/под ней — контур; `Delete` удаляет (отмена возвращает), `Esc` снимает; «Структура → Таблица → Выделить/Удалить таблицу»; название добавляется/убирается в любой момент.
- [ ] Таблица → «Границы»: без границ / только внешняя / только горизонтальные / все — в «Авторе», DOCX, HTML, PDF одинаково; «Линия под строкой» и «справа от столбца» — убрать и показать; объединённые ячейки не ломают линии.
- [ ] Блок с `product="Альфа Бета"` и с `outputclass="warning-box"` — над ним серая пометка «product: Альфа, Бета · class: warning-box»; «Структура → Показывать пометки атрибутов» выключает и включает.
- [ ] Д12: блок с `rev`, `status`, `importance`, `conref`, `translate` — в пометке они же (условные первыми, остальные по алфавиту, `class` последним); `id`, `xml:lang`, раскладка таблицы (`frame`, `colsep`, `valign`…) пометок не дают; значение длиннее 60 знаков обрезано многоточием.
- [ ] «Параметры страницы…» и «Оформление DOCX…» — одно окно «Оформление DOCX» с вкладками «Оформление» / «Страница»; пункт меню открывает свою вкладку; один «ОК» сохраняет обе, свой размер листа не сбрасывается.

- [ ] Карта (`.ditamap`): «Автор» — список топиков по иерархии, красные битые строки, двойной щелчок открывает топик; правка структуры в панели «Карта» сразу обновляет список; «Предпросмотр» — текст всех топиков с оглавлением.
- [ ] «Публикация → Список продуктов…»: добавить («Мой продукт» → `Мой_продукт`), удалить, экспорт в файл, импорт в другом проекте (объединить / заменить); список сохраняется между запусками (`.ditastudio-products`).

- [ ] Изменить заголовок топика и перейти в другой блок: вопрос «Переименовать файл…»; «Да» — файл и ссылки в карте обновлены; «Нет» — файл цел, повторно не спрашивает; напечатать и стереть — вопроса нет.

## 4. Документ — источник (XML)

- [ ] Открытие документа — исходный XML в AvalonEdit с подсветкой.
- [ ] Ручное редактирование, сохранение, повторное открытие — изменения сохранены.
- [ ] Невалидный XML при сохранении — сообщение об ошибке, файл не портится.
- [ ] Файл с BOM и без BOM — оба открываются и сохраняются без порчи кодировки.
- [ ] Файл в кодировке, отличной от UTF-8 (напр. windows-1251 с явным `encoding=`), — либо корректно читается, либо явная ошибка (не тихая порча текста).
- [ ] Документ с внутренним DOCTYPE/ENTITY (потенциальный XXE) — сущности не подгружают произвольные внешние файлы/URL без ведома пользователя.
- [ ] Очень большой XML-файл (десятки МБ / сотни тысяч строк) — открывается за разумное время, не виснет UI-поток.
- [ ] Пустой файл (0 байт) с расширением .dita — открытие даёт понятную ошибку, не краш.
- [ ] Файл с некорректным `class`-атрибутом (не по конвенции DITA) — не роняет DisplayKind-эвристику.

## 5. Документ — режим «Автор» (WYSIWYG)

- [ ] Блочные элементы (абзац, список, примечание, блок кода, таблица) — отдельные плашки.
- [ ] Фразовые элементы вложены (напр. `<b><image/></b>`) — не схлопываются, не теряют содержимое.
- [ ] Enter/Backspace/Tab внутри плашки — только валидные по контент-модели операции.
- [ ] Показывать имена элементов — переключатель меняет отображение тегов.
- [ ] Отмена структурного изменения (Ctrl+Alt+Z) / Повторить (Ctrl+Alt+Y).
- [ ] Обычный набор текста — Ctrl+Z самого редактора блока (WPF — RichTextBox), не через UndoStack.
- [ ] Enter в середине абзаца с `b`/`codeph`/ссылкой — разметка сохраняется по обе стороны (Avalonia; в WPF разметка при разделении терялась).
- [ ] Пункт списка с текстом и вложенным списком, `note` из абзацев, ячейка из абзацев — текст правится отдельными участками, вложенные блоки — обычными блоками, а не плашкой (Avalonia).
- [ ] Отмена набора внутри блока возвращает удалённый фрагмент вместе с его разметкой и плашками (Avalonia).
- [ ] Правый клик по слову с ошибкой — варианты исправления, «Пропустить все», «Вырезать/Копировать/Вставить»; исправление сохраняет оформление слова (Avalonia).
- [ ] Enter/Backspace в топике из нескольких сотен абзацев — без заметной задержки (перестраиваются только затронутые блоки).
- [ ] Документ вообще без содержимого в body (пустой `<conbody/>`) — плашки не падают на пустом дереве.
- [ ] Документ только с заголовком, без тела.
- [ ] Список с глубокой вложенностью (ul>li>ul>li>ul…, 5+ уровней).
- [ ] Таблица 1×1, таблица без заголовка, таблица с colspan/rowspan на границе.
- [ ] Вставка/удаление в позиции, где контент-модель это запрещает, — операция отклоняется, а не создаёт невалидный DITA молча.
- [ ] Копипаст текста с внешним форматированием (из Word/браузера) в плашку — не протаскивает чужой HTML/RTF как DITA-разметку.
- [ ] Очень длинный абзац без переносов (перфоманс переноса строк в редакторе блока).

## 7. Track changes

- [ ] Пометить как вставленное/удалённое — `status="new"/"deleted"` + `tcauthor`/`tcdate`.
- [ ] Принять правку — вставленное остаётся, удалённое физически убирается.
- [ ] Отклонить правку — вставленное убирается, удалённое возвращается.
- [ ] Узел `status="deleted"` не проходит проверку содержимого до Accept/Reject, но не ломает документ.
- [ ] Вложенные правки: удаление родителя, у которого дочерний узел помечен как вставленный, — порядок Accept/Reject не портит дерево.
- [ ] Accept/Reject без выделения/без активной правки — команда не падает, ничего не делает.
- [ ] Track changes на узле, участвующем в conref (изменение в источнике conref) — резолвер не подхватывает `status="deleted"` контент как активный.
- [ ] Два подряд tracked-изменения на одном узле (insert, потом delete) — итоговое состояние детерминировано.

- [ ] HTML — рендер как есть.

- [ ] Правка `title` с включённой боковой панелью: по уходу фокуса всё равно спрашивает о смене имени файла.
- [ ] Смена условий сборки/CSS отражается в предпросмотре после обновления.
- [ ] Открыть предпросмотр в браузере дожидается генерации перед открытием.
- [ ] Индикатор статуса показывает состояние генерации (в процессе/готово/ошибка).
- [ ] Быстрое повторное переключение формата (HTML→PDF→DOCX→HTML) до завершения предыдущей генерации — итоговый показанный формат соответствует последнему выбору (`_previewRequestId` реально защищает).
- [ ] Закрытие вкладки документа во время идущей генерации предпросмотра — не падает, не оставляет лишний процесс браузера (Chromium/WebView2).

## 16. Комбинации фич (интеграционные сценарии)

Каждая фича по отдельности может работать, а вместе — нет. Матрица важных пересечений:

- [ ] Track changes + XLIFF: экспорт документа с `status="new"/"deleted"` узлами — удалённый текст либо не попадает в сегменты, либо явно помечен.
- [ ] Track changes + conref: правка в источнике conref, принятие/отклонение не рвёт целевые ссылки.
- [ ] Условия сборки (.ditaval) + внешний DTD: специализированные элементы корректно исключаются/флагуются по `@class`.
- [ ] Условия сборки + предпросмотр DOCX-приближённо: исключённый контент не появляется ни в HTML, ни в DOCX-скине.
- [ ] Плагин-правило валидации + встроенное правило на одном и том же узле — оба сообщения присутствуют одновременно.
- [ ] Плагин формата публикации + условия сборки — плагин получает уже отфильтрованное дерево, а не полное.
- [ ] Плагин формата публикации + внешний DTD — плагин видит элементы специализации через общий `ElementDef`, не падает на незнакомом `DisplayKind`.
- [ ] Переименовать id + conref, ссылающийся на этот id, + track changes на той же ветке — все три операции подряд не рассинхронизируют документ.
- [ ] Экспорт в XLIFF → импорт перевода → повторная публикация HTML/PDF/DOCX — переведённый текст доходит до всех трёх форматов.
- [ ] Поиск/замена по всему проекту в документе, который сейчас открыт в режиме «Автор» с несохранёнными изменениями, — итог на диске согласован с тем, что видно в редакторе.
- [ ] Подключённый проект-источник ключей + внешний DTD одновременно в двух разных проектах — конфликт специализаций (см. раздел 20) не путается с конфликтом ключей.

## 17. Граничные и невалидные входы (устойчивость/безопасность)

- [ ] DTD с XXE-подобной внешней сущностью (`<!ENTITY x SYSTEM "file:///...">`) — `DtdReader` не подгружает произвольные локальные/сетевые ресурсы без ведома пользователя.
- [ ] DTD с рекурсивным раскрытием параметрических сущностей (billion laughs — сущность ссылается сама на себя или взрывной рост) — есть предел, не OOM/не зависание.
- [ ] Href/conref со значением `../../../../etc/something` (path traversal за пределы проекта) — резолвер не читает/не пишет произвольно за пределами ожидаемой области, либо явно предупреждает.
- [ ] Глубоко вложенный XML (тысячи уровней вложенности) — рекурсивные обходы (`ModelAutomaton`, `XliffConverter.WalkForExport`, `InlineEditor.AppendChildren`) не переполняют стек.
- [ ] Документ с элементом, которого нет ни в основном каталоге, ни в подключённом DTD, — валидатор/автор-режим сообщают «неизвестный элемент», не падают.
- [ ] `.ditaval` с несуществующим/некорректным значением `action` (не exclude/include/flag/passthrough) — игнорируется с предупреждением, не крашит парсер.
- [ ] Циклический conref (A conref на B, B conref на A) — резолвер обнаруживает цикл, не зацикливается бесконечно.
- [ ] Циклическая карта (mapref сам на себя, транзитивно) — построение дерева карты не зацикливается.
- [ ] Файл проекта с NTFS-зарезервированными именами (`CON`, `PRN`, `aux.dita`) — на Windows это ловушка сама по себе, проверить, что редактор не падает при попытке открыть/создать такое.
- [ ] Огромный одиночный DITA-файл (сотни МБ) — открытие либо укладывается в разумное время, либо явно отказывает с понятным сообщением (не безлимитный OOM).
